## Executive Summary

v0.3.4 delivers the most significant functional advancement to the EHRM Training & Booking Canvas app since the project baseline. While releases v0.3.0 through v0.3.2 focused on CI/CD infrastructure, workflow automation, and repository hygiene, this release is entirely driven by hands-on development improvements made directly inside the Power Apps canvas editor. The result is a substantially more capable, role-aware, and user-friendly training room reservation application.

Ten distinct improvement areas were implemented and are documented in full below:

1. **Role-Based Access Control** — 8-tier permission model replacing the previous binary admin check

4. **Reservation Detail Enhancements** — Relabeled fields, clearer layout, grid-based confirmation screen
5. **Calendar Screen Modernization** — New Daily Calendar screen, grid layout upgrades across all three calendar views

## Changes

### Canvas App — Role-Based Access Control (Dashboard)

The `Dashboard` screen is the entry point for all users and previously enforced only a simple binary "admin / not admin" check based on whether the current user appeared in the `DeskAccessControl` SharePoint list. This has been completely replaced with a multi-tier RBAC system.

**How it works:**

On `Dashboard.OnVisible`, the app now:
1. Calls `Refresh(DeskAccessControl)` to guarantee fresh permission data before any evaluation.
2. Clears and re-populates the `userAccessDemographics` collection with the current user's full access control record.
3. Resolves `userAccessLevel_text` from the `AccessLevel_Text` column of the matched record.
4. Clears `colMenu` and rebuilds it from scratch based on the resolved access level.

**Access tiers and resulting menu behavior:**

| Access Level | Who it's for | Menu Presented |
|---|---|---|
| `SuperUser` | Power users / EHRM leads | Full menu — all navigation items |
| `AppAdmin` | Application administrators | Full menu — all navigation items |
| `Manager` | Service managers | Full menu — all navigation items |
| `ServiceChief` | Service line chiefs | Full menu — all navigation items |
| `ProjectLeader` | Project/CLT leads | Full menu — all navigation items |
| `User` | Standard training participants | Reduced menu — booking + self-service |
| `View-only` | Observers / read-only stakeholders | Minimal menu — calendar views only |
| `AccessDenied` | Explicitly blocked individuals | Empty menu — app locked out |

**Additional Dashboard changes:**
- **Upcoming Reservations gallery filter** simplified — removed the ambiguous `OR 'Created By'.Email` condition so only reservations where you are the explicit "Reserved By" party appear in the dashboard preview.
- **"View calendars!" button** — renamed from "Click to see calendar"; resized for better visual balance.
- **Reason label** — expanded height and added scroll support to accommodate multi-line reservation reason text without clipping.

### Canvas App — Intelligent Scheduling (chkWeekDays / Select Date & Time)

The booking flow's date/time selection screen received the largest cumulative update. Users booking a training room now experience a significantly smarter and more guided scheduling experience.

**Smart default start time:**

When the screen opens, the app automatically calculates and pre-selects a start time rounded up to the nearest 15-minute boundary from the current moment:
- Open at 9:07 AM → pre-selected to **9:15 AM**
- Open at 2:46 PM → pre-selected to **3:00 PM**
- Open at 10:30 AM → pre-selected to **10:30 AM** (already on boundary)

This eliminates the need to manually scroll past irrelevant time options and reduces booking errors from leaving an arbitrary pre-selected time.

**Automatic 1-hour event duration:**

When the user clicks Continue, `varEventEndTime` is automatically set to `varEventStartTime + 60 minutes`. The End Time field pre-populates with this calculated value, which the user can adjust. This reflects the common real-world case of a 1-hour training session.

**New scheduling options:**

Three new dropdown controls have been added to the date/time screen:
- **Importance**: Normal / High / Low — stored as `varImportance` for inclusion in calendar event metadata.
- **Reminder**: Configurable minute-based reminder interval — stored as `varReminder`.
- **Event Recurrence**: None / Daily / Weekly — stored as `varRecurrence`. When "Daily" + "Every weekday" is selected, Saturday and Sunday are automatically excluded from the recurrence set.

**Live conflict detection:**

The bottom section of the date/time screen now shows **"Existing reservations already booked on the selected date"** — a live gallery that queries `Desk Reservations` for any bookings overlapping the selected date. This gives schedulers visibility into what is already reserved before committing to a time slot.

**Extended booking horizon:** `DaysAheadRestriction` expanded from 180 → **230 days**, allowing training sessions to be scheduled nearly 8 months in advance.

### Canvas App — Appointment Management (MyAppts / My Reservations)

**Explicit action buttons in upcoming reservations gallery:**

The upcoming reservations list previously relied on icon-only navigation (easy to miss or accidentally trigger). Two clearly labeled buttons now appear in each gallery row:
- **"View This"** (green) — navigates to the `Reservation Details` screen for the selected booking.
- **"Cancel This"** (red) — triggers a confirmation dialog before any cancellation action.

**Cancellation confirmation modal:**

Clicking "Cancel This" or the CANCEL button no longer immediately executes. Instead, a modal overlay appears with:
- **"Confirm Cancellation?"** — clearly labeled intent
- **"NEVERMIND"** (red) — dismiss and return to the list
- **"CONFIRM"** (navy) — proceed with cancellation

This prevents accidental cancellations of live reservations and aligns with standard UX safety patterns for destructive actions.

**Past reservations — improved filtering:**

The Previous tab now correctly surfaces all historical and inactive reservations. Previously, the filter only caught records whose `Check Out From` date was in the past. The updated filter also includes records where `Active_choice` is blank or explicitly set to `"false"`, ensuring manually deactivated or cancelled bookings always appear in the historical view regardless of their date fields.

### Canvas App — Calendar Screen Modernization

**New `scrn_DailyCal` screen (replaces `scrn_WeeklyCal_1`):**

The old daily calendar screen (`scrn_WeeklyCal_1`) has been replaced by a new, purpose-built **Daily Calendar List** screen (`scrn_DailyCal`) titled "Daily Training Room List". This screen presents a tabular list view of all training room reservations for the current day, with columns for ID#, Desk Reservation Info, and POC Comments. It is built on the modern Power Apps container grid layout system (6 columns × 6 rows), enabling proper responsive scaling.

All navigation references to `scrn_WeeklyCal_1` throughout the app have been updated to point to `scrn_DailyCal`.

**Grid layout upgrades:**

The two existing calendar screens were also upgraded to the modern container grid layout:
- `scrn_WeeklyCal` (`Container1`) — now 6×6 grid
- `scrn_MoCalendar` (`Container7`) — now 6×6 grid

The Monthly Calendar screen now provides **Weekly** and **Daily** view toggle buttons. The Weekly Calendar provides **Monthly** and **Daily** toggles. All three views are fully interconnected with consistent navigation.

### Canvas App — App Version Tracking

`App.OnStart` (previously empty) now initializes a global project version string on every app launch:

```powerfx
Set(varGetRepo_ProjectVersion, "0.3.4");
```

This variable is displayed in the top-left corner of the Dashboard screen, giving operators and support staff immediate version identification without needing to check external systems. Commented-out code in `OnStart` documents intended future integration with GitHub release APIs and the Power Apps for Makers connector to auto-fetch the latest version dynamically.

## Upgrade Notes / Configuration Requirements

> **Important for administrators:** The new RBAC system requires that every user in the `DeskAccessControl` SharePoint list have their `AccessLevel_Text` column populated with one of the valid access level values listed above. Users without a matching row, or with a blank `AccessLevel_Text`, will receive an empty menu (effectively `AccessDenied` behavior) until their record is configured.
