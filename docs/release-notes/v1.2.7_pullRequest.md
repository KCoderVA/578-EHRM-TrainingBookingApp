## Detailed breakdown

### 1. Automated report ingestion

The Outlook `OnNewEmailV3` trigger accepts attachment-bearing messages sent to the configured mailbox
from `TMS-NoReply@va.ns2cloud.com`. For each attachment whose name ends with lowercase `.csv`, the flow
retrieves its bytes and performs two SharePoint operations after retrieval:

- overwrite `TMS_Reports/TMSProgramCompletion_DetailedReport.csv`;
- create a dated copy in `TMS_Reports/archives`.

The canonical file is the primary data source for the internal
`578 EHRM Training Details Reports.pbix`. Power BI refresh is configured separately.

### 2. Parsing boundary documented

The SharePoint actions receive the original attachment bytes. The subsequent Compose/Apply-to-each
branch splits rows and extracts the first column as `Program ID`, but neither its array nor Select output
is consumed. This PR deliberately documents the behavior as raw attachment ingestion with preliminary
CSV inspection, not as a transformed-data pipeline.

### 3. Operations, privacy, and deployment guidance

The new component README documents connection permissions, the stable SharePoint/Power BI contract,
import steps, acceptance tests, and handling requirements for employee training records. The deep-dive
analysis inventories all actions and ranks hardening work.

## Admin action required before deploying

1. Map the package's Office 365 Outlook and SharePoint Online embedded connections.
2. Verify mailbox access and the expected TMS sender.
3. Ensure the canonical SharePoint file and archive folder exist with least-privilege permissions.
4. Run a controlled report email through the flow and verify both SharePoint writes.
5. Refresh the Power BI dataset and reconcile headers, row counts, and completion-status totals.
6. Add the flow to the Dataverse solution and re-export `solution.xml`; the legacy package does not
	expose the exact flow component `schemaName`, so this PR does not fabricate one.

## Known issues / follow-up items

- The extension check is case-sensitive and only matches lowercase `.csv`.
- Attachment-dependent parsing sits outside the CSV condition and can reference a skipped action.
- Raw `utcNow()` may generate an archive filename containing SharePoint-unsafe punctuation.
- The CSV parser is not quote-aware, and its current outputs are unused.
- There is no exact subject/report-name allowlist or explicit failure-notification branch.
- Multiple CSV attachments can target the same canonical file.
