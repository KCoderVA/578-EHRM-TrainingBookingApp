## Canvas app changes - detailed breakdown

### 1. Screen topology modernization

Two screens were added (`ManageUsers`, `CreateMeeting`) and three legacy screens were removed (`alt_ManageDesks`, `Screen1`, `Screen2`). This shifts the app toward explicit user-management and structured meeting workflows while removing obsolete utility/alternate paths.

### 2. Data-source and connector expansion

SharePoint bindings were expanded to include `MasterScheduleList`, `SuperUserList`, `backupList_DeskReservations`, and `Learning Lab Sessions`. Connection action usage now includes additional Outlook and Users operations (`SendEmailV2`, `SearchUserV2`, `UserPhotoV2`) to support richer communication and profile flows.

### 3. Reservation patch pipeline hardening

`Confirm` retained and strengthened its multi-path persistence strategy: main patch path, fallback path, and backup-list persistence. This improves resilience for booking writes and downstream audit/recovery handling.

### 4. Version identity and metadata alignment

`varRepoVersion`, package naming, and manifest description are now synchronized at `0.12.2`. `BindingErrorCount` was reduced from `329` to `120`, reflecting cleanup progress while retaining a known residual remediation queue.

## Known issues / follow-up items

- **Residual binding issues remain:** `BindingErrorCount` is reduced but non-zero (`120`); App Checker cleanup should continue before full production hardening closeout.
- **Deferred Outlook linkage fields:** `OutlookEventID`, `OutlookSeriesID`, and `ParentReservationID` are still intentionally deferred in the app layer and require companion automation completion.
- **Default access behavior must be validated:** Ensure onboarding/role default logic is validated in each target environment to avoid over- or under-permissioning at first launch.
