## Executive Summary

This release focuses entirely on repository organization and documentation accuracy — there are no functional changes to the Canvas app or Power Automate flow. The `src/sharePoint/` component was restructured from a flat per-list sample layout into a cleaner `list/<listName>/local/` + `searchConfig/` pattern, and a brand-new `src/analytics/` component was introduced to house Power BI and SQL reporting assets that had previously only existed as aspirational (unpopulated) entries in the project documentation. Separately, a `.gitignore` gap was closed that had left a large local screen recording completely untracked by any ignore rule, and `docs/PROJECT_STATUS.md` — which had drifted out of date since v0.3.6 — was brought fully current.

4 distinct improvement areas were implemented and are documented in full below:

1. **SharePoint restructuring** — new `list/<listName>/local/` layout, new `searchConfig/` export, new `Schedule` list scaffold
2. **New Analytics component** — first tracked Power BI report template, scaffolded SQL folders
3. **`.gitignore` hardening & tracking cleanup confirmation** — generic `local/` folder rule; confirmed prior cleanup items are resolved
4. **Documentation catch-up** — `docs/PROJECT_STATUS.md` full refresh, component READMEs, `copilot-instructions.md` accuracy pass

## Changes

### SharePoint — Restructured list export layout (`src/sharePoint/`)

Through v0.3.7, sanitized SharePoint sample data lived in a flat per-list layout (`Desk Reservations/`, `DeskAccessControl/`, `Desks/`). This release replaces it with a `list/<listName>/local/` pattern that clearly separates raw, potentially sensitive local exports from any tracked artifacts.

**New structure:**

| Path | Contents | Tracked? |
|---|---|---|
| `list/deskAccessControl/local/` | `DeskAccessControl.csv` | No (local-only) |
| `list/deskReservations/local/` | `Desk Reservations.csv` | No (local-only) |
| `list/desks/local/` | `Desks.csv`, `Desks.xlsx`, versioned variants | No (local-only) |
| `list/schedule/local/` | Staging data for a new, not-yet-created list | No (local-only) |
| `searchConfig/SearchConfiguration.xml` | SharePoint search configuration export | **Yes** |

**New `Schedule` list (scaffold):** A 4th list folder, `list/schedule/`, has been created and staged with source data (`SULL_Jesse_Brown_Schedule_7.10.26 - Integrated.xlsx`), but the list itself has not yet been created in SharePoint and no schema has been exported. This is an early step toward the ongoing "desk reservation" → "training booking" terminology migration already tracked as a roadmap item.

The prior flat layout has been archived locally to `archive/src/sharePoint/`.

---

### New component — Analytics (`src/analytics/`)

Introduces a dedicated home for Power BI and SQL reporting assets, replacing the flat `src/powerBI/` and `src/sql/` paths that `copilot-instructions.md` had described since early versions of the project but which were never actually populated.

**What's included today:**
- `powerBI/.pbit/Signup Tool.pbit` — first tracked Power BI report template (sign-up/attendance analytics).
- `powerBI/.pbix/` — corresponding live-data binary, intentionally git-ignored (large binary format; the `.pbit` template is the source-controlled artifact).
- `sql/procedures/`, `sql/queries/` — scaffolded and currently empty; no database scripts have been written yet.

This is an early-stage component; see `src/analytics/README.md` for current status.

---

### `.gitignore` — Local-folder hardening and tracking-cleanup confirmation

**What changed:**

A new generic rule, `**/local/` (§11), now ignores any folder literally named `local` anywhere in the repository — regardless of file extension. This closes a real gap discovered during this release: a ~106 MB app walkthrough screen recording (`assets/local/video/SU LL Sign up APP EHRMIO.webm`) had no covering ignore rule at all (the existing rules only covered specific file extensions like `.csv`/`.xlsx`, not video formats).

Separately, this release confirms and documents that a cleanup item flagged since the v0.3.6 changelog entry — "3 files under `config/` and 10 sanitized CSVs under `src/sharePoint/` remain tracked pending `git rm --cached`" — has already been completed. `git ls-files` confirms zero tracked files remain under either path at `HEAD`. The stale "pending" language in `.gitignore` and `docs/PROJECT_STATUS.md` has been corrected to reflect the resolved state.
