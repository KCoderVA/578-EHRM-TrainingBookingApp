# PR: v1.2.6 — Canvas app + automation: DebuggingScreen height proof of concept

## PR Summary

This PR delivers the **v1.2.6 maintenance release** for the 578 EHRM Training App. It documents a verified live-coauthoring update that changes `DebuggingScreen.Height` from `App.Height` to `App.Height + 1`, advances the app's active `varRepoVersion` from v1.2.4 to v1.2.6 to match the latest concurrent project version, and revises the reusable Copilot release prompt around the proven Canvas Authoring workflow.

The Canvas edits were compiled through the Power Apps authoring service and verified by downloading a fresh copy from the connected coauthoring session. The project `VERSION` advances from v1.1.20 to v1.2.6 so the repository release matches the live Canvas component.

## Canvas app changes — detailed breakdown

### 1. DebuggingScreen height

The top-level `DebuggingScreen.Height` formula now evaluates to one pixel more than the app height:

```powerfx
App.Height + 1
```

The prior expression was `App.Height`. This deliberately small behavior change provides a visible and technically precise proof of the live Canvas coauthoring edit path.

### 2. Canvas semantic version

`App.OnStart` now initializes:

```powerfx
Set(varRepoVersion, "1.2.6")
```

The prior active value was `"1.2.4"`. A fresh synchronization from the authoring server confirmed both this value and the height expression after compilation.

### 3. Autonomous release protocol

The reusable `.github/prompts/autonomousCanvasAppChangeRelease.prompt.md` now directs Copilot to:

- interpret the user's plain-language Canvas request;
- synchronize and inspect the connected live app;
- edit and compile the synchronized YAML;
- verify propagation through a separate fresh synchronization;
- align Canvas and repository semantic versions;
- update changelog and release documents;
- execute and monitor `enterpriseCommitGuide.ps1`;
- verify the merged enterprise repository release.
