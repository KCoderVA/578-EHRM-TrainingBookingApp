## Executive Summary

Version 1.2.7 adds an automated reporting bridge between the VA Training Management System (TMS), a
secured SharePoint document library, and the internal Power BI report used by Edward Hines Jr. VA
Hospital management and executives. A recurring TMS report email can now replace the stable
`TMSProgramCompletion_DetailedReport.csv` source file and retain an archive copy without manual file
handling.

Four improvement areas are included:

1. **Automated TMS ingestion** - receives and retrieves recurring CSV report attachments.
2. **Stable SharePoint publication** - updates the canonical Power BI source and archives each delivery.
3. **Source-level documentation** - inventories the action tree, connectors, contracts, tests, and risks.
4. **Project integration** - aligns the solution manifest, analytics lineage, status, and release docs.

## Changes

### Power Automate - TMS email ingestion

The new `578EHRMTrainingApp_parseTMSReport-updateSharePointCSV` flow monitors the configured Outlook
mailbox for messages from the TMS automated reporting service that include attachments. It evaluates
each attachment and retrieves items whose names end with lowercase `.csv`.

### SharePoint - canonical report and archives

For each accepted attachment, the flow uses SharePoint Online to:

- overwrite `/Shared Documents/TMS_Reports/TMSProgramCompletion_DetailedReport.csv` with the original
  attachment bytes;
- attempt to create a timestamped copy under `/Shared Documents/TMS_Reports/archives`.

The stable canonical path allows the Power BI connection to remain unchanged as new TMS deliveries
arrive. The archive provides historical source snapshots subject to SharePoint retention and access
governance.

### Analytics - Power BI lineage

The canonical SharePoint CSV is the primary connected source for the internal
`578 EHRM Training Details Reports.pbix`, which supports oversight of completed and incomplete EHRM/FEHR
training for Hines employees. Dataset refresh remains a separate Power BI service schedule; this flow
does not invoke refresh.

### Documentation and analysis

The new component README and v1.2.7 deep-dive analysis cover:

- trigger filters and every action in execution order;
- Office 365 Outlook and SharePoint Online connection requirements;
- the SharePoint path and Power BI integration contract;
- deployment, validation, security, and privacy requirements;
- prioritized reliability and data-integrity improvements.

The analysis confirms that the production SharePoint file is a byte-for-byte copy of the attachment.
The current row-processing branch extracts the first CSV column as `Program ID`, but those transient
outputs are not persisted and do not transform the Power BI source.

## Upgrade Notes / Configuration Requirements

Before production use, an administrator must map the Outlook and SharePoint connections, verify the
mailbox and sender filters, confirm the canonical file and archive folder exist, and grant the connector
identities only the required permissions. Run a controlled email test, compare the resulting SharePoint
file to the attachment, and verify the next Power BI refresh reconciles to TMS.

Add the flow to the Dataverse solution and re-export the solution manifest before deploying it as part
of the managed solution. The legacy flow package does not expose the exact Dataverse component
`schemaName`, so v1.2.7 documentation intentionally does not invent a root-component identity.

Employee training records are internal and potentially sensitive. Keep CSV and PBIX artifacts out of
public source control and apply appropriate SharePoint access, retention, and sensitivity controls.

## Known Issues

- Only lowercase `.csv` filenames match the current condition.
- Parsing actions are outside the true branch and can reference skipped attachment output.
- The archive filename uses raw `utcNow()` and should be changed to a SharePoint-safe timestamp.
- Literal comma/newline splitting is not a standards-compliant CSV parser; parsed output is currently unused.
- Exact report subject/filename validation and explicit operator failure alerts are not yet implemented.
