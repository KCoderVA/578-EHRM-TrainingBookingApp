## Detailed breakdown

### 1. New flow — `SendReminders` ("Send Email Reminder")

A new Power Automate flow that emails scheduled users a **"You are scheduled for EHRM Learning Lab training!"** confirmation/reminder. It reads the user's details from the `DeskAccessControl` SharePoint list (display name, email/UPN, access level/role, scheduling admin, and access window) and renders them in an Adaptive Card email body. The standalone card design lives at `SendReminders/adaptiveCards/v0.12.4_flowSendReminders_adaptiveCard.json`; the flow definition also embeds the card inline.

This directly addresses the long-standing roadmap item to build the reminder flow.

> **Admin action required before production use:** import/enable the flow in the target Power Platform environment, authorize its Office 365 Outlook + SharePoint connections, and validate the trigger conditions, recipient resolution, and send-time scheduling.

### 2. `AppUserList` re-export (v0.1.0 → v0.1.1)

The existing access-control flow was re-exported from Power Automate: `apisMap.json`, `connectionsMap.json`, `definition.json`, and `manifest.json` were refreshed, and its `.json` export was renamed with the `v0.12.2_` project-version prefix to match the repository's versioned-artifact naming convention. No behavioral change beyond the refreshed connection references.

### 3. Documentation & workspace tidy

All project docs were updated to v0.12.3 (`VERSION`, `README.md`, `CHANGELOG.md`, `docs/PROJECT_STATUS.md`, `src/powerAutomate/README.md`, and both subcomponent READMEs). The two loose `flowSendReminders_adaptiveCard.json` files were moved off the repo root — the current v0.12.4 card into `src/powerAutomate/SendReminders/adaptiveCards/`, and the superseded v0.12.2 card into local-only `archive/`.
