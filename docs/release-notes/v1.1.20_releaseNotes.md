## Executive Summary

v1.1.20 hardens the app's most important transaction — booking a training session — and finally gives staff real in-app help. The `Confirm` screen's single "Submit" button was re-architected into a small orchestrator that runs each step (calendar invite, reservation write, Super User sync, confirmation email) as a dedicated action and then uses a verification **timer** to confirm success before showing the Success screen; reservation writes now always mirror to a backup list and degrade gracefully through a fallback cascade. The in-app Help screen was rebuilt from stale text into a 10-step Quick-Start guide (with a full changelog view for admins), and the class/scenario picker now reads Hines-scoped data and honors a new active-session flag. This release impacts all ~100–150 staff who register for EHRM Learning Lab training. One functional defect remains open — a binding-error regression on the `Success` screen — which will be corrected in a follow-up patch.

7 distinct improvement areas are documented below:

1. **Resilient booking-commit orchestration** — verified, timer-gated submit.
2. **Tiered both-lists fallback cascade** — graceful degradation, backup always written.
3. **Rebuilt Help screen** — end-user Quick-Start guide + admin changelog.
4. **Smarter class/scenario picker** — Hines-scoped, active-session-filtered, cascade-reset.
5. **New `sessionActive_text` reference** — hide inactive sessions.
6. **Naming-convention & maintainability cleanup** — consistent control names, email `Cc` fix.
7. **Experimental Screen1 data-explorer** — dev/admin only, not on the menu.

## Changes

### Canvas app — Resilient booking-commit orchestration (`Confirm`)

Previously a single `btnSubmit` performed the calendar post, reservation patch, Super User sync, and email inline and then navigated straight to Success — so a silent failure could still show "Success."

**How it works:** `btnSubmit` now `Select()`-chains dedicated buttons and defers navigation to a new `timer_selectBtnsThenNavigate`. The timer rolls per-step flags into `varAllOK` and only then navigates, with a grace delay so notifications render.

```powerfx
// timer_selectBtnsThenNavigate.OnTimerEnd (abridged)
Set(varAllOK, varCalendarOK And varEmailOK And varPatchSuperUsersOK And varAnyListPatchOK);
If( Lower(varRealEmail) = "kyle.coder@va.gov", Notify(...), Navigate(Success) );
```

| Grace delay | When |
|---|---|
| 2 s | Patch succeeded |
| 8 s | Patch failed |
| 12 s | Debug tier reached |

### Canvas app — Tiered both-lists fallback cascade (`Confirm`)

Reservation writes were reorganized into a four-tier cascade, and every tier writes to **both** `'Desk Reservations'` and `backupList_DeskReservations`:

| Tier | Button | On failure → |
|---|---|---|
| 1 | `btnPatch_detailedPrimary` | `btnPatch_detailedSecondary` |
| 2 | `btnPatch_detailedSecondary` | `btnPatch_simplePrimary` |
| 3 | `btnPatch_simplePrimary` | `btnPatch_debugSimplified` |
| 4 | `btnPatch_debugSimplified` | logs `"DEBUG …"` rows + error notify |

Success is measured per result-collection (`CountRows > 0 And CountIf(Not(ok)) = 0`); a per-submission GUID (`varSubmissionID`) tags the rows. Controls were renamed to `btnOutlook_*` / `btnPatch_*`; the legacy monolithic `btnOldSubmit` is retained but disabled.

### Canvas app — Rebuilt in-app Help screen (`ReleaseNotes`)

The stale static Help content was replaced by two audience-specific views:

| Audience | Control | Content |
|---|---|---|
| End users (`user_isAdmin = false`) | `htmlText_userGuide` | 10-step Quick-Start guide + "Handy tips" |
| Admins (`user_isAdmin = true`) | `htmlText_releaseNotes` | Full project changelog (HTML render) |

### Canvas app — Smarter class/scenario picker (`POCSUPERVISOR`)

The Role → Scenario → Date/Time → Location picker was re-pointed from live SharePoint queries to Hines-scoped in-memory collections (`col_nationalEHRMLearningLabSessions`, `col_MasterSchedule`), now hides inactive sessions via `sessionActive_text`, applies consistent "…NOT LISTED!" placeholders, and resets downstream selections when Role/Scenario change. (The Edit-form data-card churn is reordering only — no bound-column change.)

### Canvas app — New `sessionActive_text` reference

The app now uses a `sessionActive_text` value on `MasterScheduleList` so a scheduled session can be switched off; the Date/Time picker treats a session as bookable when the value is blank or not `"false"`.

### Canvas app — Naming/cleanup & misc

`Dashboard` `Timer3` → `timer_loadGlobalVariables`; `App` `varRepoVersion` stamp + `Text("Hines")` simplification; `DebuggingScreen` dev-cleanup lines disabled; `chkWeekDays` disarms the new Confirm timer var; confirmation-email `Cc` typo `varAttendees` → `var_Attendees` fixed. The three PM/admin `Cc` addresses remain intentionally hard-coded for resilience.
