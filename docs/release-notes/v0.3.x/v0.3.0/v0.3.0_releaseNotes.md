# EHRM Training & Booking App — Release Notes (v0.3.0)

- **Release date**: 2026-07-07
- **Release type**: Feature (GitHub Actions/workflows overhaul, repo automation)
- **Previous release**: v0.2.1 (2026-07-07)

## Executive summary

v0.3.0 overhauls the repository's GitHub Actions/workflows from disabled stubs into a fully functional CI/CD automation suite designed for a solo-developer Power Platform project. The release introduces a `VERSION` file as the single source of truth for semantic versioning, adds 5 new workflows (PR auto-setup, version bumping, repo linting, security scanning, and release automation), enhances 3 existing workflows, removes 2 that provided no value, and fixes 3 file-placement bugs.

No functional changes are intended to the Power Apps Canvas app or Power Automate flow logic.

## Highlights

- **`VERSION` file** — all workflows and scripts now read the version from one place instead of hardcoding it in multiple files
- **One-click version bumping** — `version-bump.yml` scaffolds the next release from the GitHub Actions tab
- **Automated PR setup** — every new PR gets auto-assigned, a contextual review checklist, and a Copilot code review request
- **Security scanning** — PRs that touch source files are scanned for GUIDs, SharePoint URLs, VA emails, and SSN-like patterns
- **Repo structure validation** — required files, JSON integrity, and file placement are verified on every PR
- **Automatic GitHub Releases** — pushing a `v*` tag creates a Release with your pre-written notes
- **Comprehensive documentation** — every workflow file includes detailed educational comments explaining purpose, usage, and troubleshooting

## Changes

### Added

- `VERSION` — root-level file containing `0.3.0`; read by all workflows and PowerShell scripts
- `.github/labeler.yml` — label configuration for actions/labeler@v5
- `.github/workflows/pr-auto-setup.yml` — 3 parallel jobs: auto-assign, contextual checklist, Copilot review
- `.github/workflows/version-bump.yml` — manual trigger: updates VERSION/README/CHANGELOG/PROJECT_STATUS, creates release notes templates, opens draft PR
- `.github/workflows/repo-lint.yml` — 3 parallel jobs: structure validation, JSON integrity, file placement
- `.github/workflows/pr-security-scan.yml` — 5-pattern scan: GUIDs, SharePoint URLs, VA emails, secrets, SSN patterns in CSVs
- `.github/workflows/release.yml` — auto-creates GitHub Releases on `v*` tag push using pre-written release notes

### Changed

- `label.yml` — upgraded to actions/labeler@v5, added `[opened, synchronize, reopened]` event types
- `powerplatform-ci.yml` — added Canvas app JSON validation (all files), Power Automate flow JSON validation, fixed solution path to `config/solutions/`, added `pull_request` trigger and path filters
- `stale.yml` — tuned for solo dev: 90-day stale (was 30), 30-day close (was 14), weekly (was daily), exempt `in-progress`/`pinned`/`blocked` labels, upgraded to actions/stale@v9
- `.github/labeler.yml` — added `scripts` and `release` labels, reorganized with section comments
- All workflow `.yml` files — added comprehensive educational comment documentation

### Removed

- `greetings.yml` — first-interaction greeting (no value for solo developer; action is archived)
- `summary.yml` — AI issue summarization (requires GitHub Models; summarizes your own issues)

### Fixed

- `.github/labeler.yml` moved from `.github/workflows/` to `.github/` (where actions/labeler expects it)
- `.github/PULL_REQUEST_TEMPLATE.md` moved from `.github/ISSUE_TEMPLATE/` to `.github/` (where GitHub expects it)
- `powerplatform-ci.yml` solution path corrected from `src/solutions/` to `config/solutions/`
