# PR: v0.3.6 — repo: .gitignore security hardening, data/archive file type rules, v0.3.5 artifact rotation, documentation catch-up

## PR Summary

This PR delivers the **v0.3.6** patch release to the **578 EHRM Training & Booking App** repo — a repository hygiene and `.gitignore` security hardening update that significantly expands ignored file coverage to protect against accidental commits of sensitive VA data files (CSV/XLSX/etc.), compressed binary exports (7z, gz, rar, etc.), and local-only configuration content (`config/`). No Canvas app, Power Automate, or SharePoint components were modified. This PR also performs the v0.3.5 post-release artifact rotation and brings `README.md` and `docs/PROJECT_STATUS.md` fully up to date through v0.3.6 (those files were not updated in the v0.3.5 release).

No component versions advance in this release. Canvas app baseline remains v0.3.4; `AppUserList` flow baseline remains v0.1.0.

## Changes — detailed breakdown

### 1. .gitignore security hardening

Prior to this release, `.gitignore` covered broad Power Platform binary formats (`.zip`, `.pbix`) and OS/editor/temp files, but had three significant gaps: the `config/` directory was only partially excluded (`config/local/` and `config/logs/` only); compressed archive formats beyond `.zip` had no rules; and spreadsheet/data file types (CSV, XLSX, etc.) were entirely uncovered.

**`/config/` — full directory exclusion added:**
The entire root-level `config/` directory is now gitignored. Previously only `config/local/` and `config/logs/` were excluded; any file added to `config/architecture/`, `config/runbooks/`, or `config/tools/` would have been auto-tracked. The `/config/` rule is root-anchored and does not affect `src/config/local/` (which remains separately excluded).

> **Follow-up action required (not in this PR):** The 3 files currently tracked under `config/` (`ARCHITECTURE.md`, `ALM-RUNBOOK.md`, `alm.ps1`) will remain in the remote repo after this PR merges — `.gitignore` rules do not retroactively untrack already-indexed files. A follow-up commit must run `git rm --cached -r config/` to fully remove them.

**Compressed archive formats — 8 new rules added:**
`**/*.7z`, `**/*.gz`, `**/*.bz2`, `**/*.tar`, `**/*.tgz`, `**/*.tar.gz`, `**/*.tar.bz2`, `**/*.rar`. Previously only `*.zip` was covered. These formats are commonly produced by export tools and should never enter the source-controlled repo.

**Spreadsheet and data file types — 7 new rules added:**
`**/*.csv`, `**/*.tsv`, `**/*.xlsx`, `**/*.xls`, `**/*.xlsm`, `**/*.xlsb`, `**/*.ods`. Broadly gitignored to prevent PII-containing or sensitive VA data from being committed. Specific sanitized public-facing files can be selectively un-ignored using `!path/to/file` negation entries in `.gitignore`.

> **Follow-up note:** The 10 sanitized CSVs currently tracked under `src/sharePoint/` remain tracked — `.gitignore` does not retroactively affect already-tracked files. These can be selectively retained via negation rules or removed via `git rm --cached`.

### 2. Documentation catch-up (README.md + docs/PROJECT_STATUS.md)

`README.md` and `docs/PROJECT_STATUS.md` were not updated in the v0.3.5 release (scripts-and-tooling-only patch). This PR brings both files fully current through v0.3.6:

- **`README.md`**: Version badge v0.3.4→0.3.6; project release date 2026-07-09→2026-07-14; `config/` layout entry now notes git-ignored/local-only status as of v0.3.6; Local-only line expanded to include `config/`, data file types, and compressed archives; Documentation section links for `ARCHITECTURE.md` and `ALM-RUNBOOK.md` now shown as annotated plain text *(local-only; git-ignored)* instead of clickable hyperlinks.
- **`docs/PROJECT_STATUS.md`**: Status summary updated from v0.3.4 to v0.3.6 (Patch — repository hygiene, 2026-07-14); v0.3.5 (2026-07-10) and v0.3.6 (2026-07-14) rows added to the release history table; "What is intentionally NOT in this repository" section expanded with three new entries: `/config/` full exclusion, data file type rules, and compressed archive rules.

### 3. v0.3.5 post-release artifact rotation

`postEnterpriseCommitArchival.ps1` (introduced in v0.3.5) was executed after the v0.3.5 merge to perform the standard three-step rotation:
1. Archived `v0.3.5_commitMessage.md`, `v0.3.5_pullRequest.md`, `v0.3.5_releaseNotes.md` to `archive/docs/release-notes/v0.3.x/v0.3.5/` (local-only, git-ignored)
2. Deleted the live copies from `docs/release-notes/`
3. Created fresh `v0.3.6_*` template stubs in `docs/release-notes/` (now populated and committed here)

`VERSION` was simultaneously bumped 0.3.5→0.3.6 by the rotation script.
