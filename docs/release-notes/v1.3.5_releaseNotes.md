## Executive Summary

v1.3.5 is a Canvas-app **data-source-modernization and reliability** release. Its centerpiece re-bases the supervisor scheduling experience off the external national `Learning Lab Sessions` SharePoint list onto the app-owned `MasterScheduleList` (with a new `scenarioDescription_multitext` column and an in-app back-fill), it fixes the prior cycle's top defect (the `Success` screen's 24 binding errors, now 24 → 3), enriches user administration with full Entra/Graph profile and manager-chain capture, removes the unused Microsoft Teams connector, re-points and re-enables the printable Power BI dashboard, and completes the app-wide classic → modern control migration. It impacts supervisors/admins most directly and improves reliability for all booking users.

**8 distinct improvement areas** are documented below:

1. **Supervisor scheduling migration** — `POCSUPERVISOR` now reads `MasterScheduleList`.
2. **New `scenarioDescription_multitext` column + back-fill** — descriptions maintainable in-app.
3. **`Success` binding-error fix (24 → 3)** — correct post-booking messaging.
4. **Richer Entra/Graph user + manager capture** — `ManageUsers`.
5. **Live Graph people-pickers** — `POCSUPERVISOR`, `ManageUsers`.
6. **Microsoft Teams connector removed** — cleaner connector footprint.
7. **Power BI dashboard re-pointed & re-enabled** — `Screen1`.
8. **Classic → modern control modernization** — app-wide.

## Changes

### Canvas app — Supervisor scheduling migration (`POCSUPERVISOR`)

Previously the supervisor screen's role/scenario/date-time pickers read the national `Learning Lab Sessions` list. That data is owned upstream and matched on lookup/choice columns.

**What changed:** the active logic now reads the app-owned `MasterScheduleList` through stable text columns (`RoleName_text`, `ScenarioName_text`, `TrainingCombinedDateTime_text`, `LocationCombined_text`) and only shows active sessions (`sessionActive_text` blank or ≠ `"false"`). Legacy queries are commented out in place. This makes the picker predictable, filterable, and independent of upstream changes.

### Canvas app — New `scenarioDescription_multitext` column + back-fill (`POCSUPERVISOR` / `MasterScheduleList`)

A new multi-line text column, `scenarioDescription_multitext`, was added to `MasterScheduleList`. A supervisor button (`btn_patchMasterScheduleList_scenarioDescription_multitext`) back-fills it, patching only rows that are blank or out-of-date.

### Canvas app — `Success` status-summary fix (`Success`)

The v1.1.20 booking-commit refactor left the `Success` screen referencing retired flag variables, producing 24 binding errors.

**What changed:** the status summary was rewritten against the current tier flags:

| Field | Before | After |
|---|---|---|
| "Main reservation list" | `varMainOK` (undefined) | **`varDetailedListPatchOK`** |
| "Backup reservation list" | `varBackupOK` (undefined) | **`varFallbackOK`** |
| "Backup (simple) reservation list" | `varBackupSimpleOK` (undefined) | **`varSimpleListPatchOK`** |
| "Email notification sent" | *(not shown)* | **`varEmailOK` / `varSimpleListPatchOK`** |
| "SuperUser list patched" | always shown | **gated by `user_IsSuperUser`** |

`CanvasManifest.BindingErrorCount` fell **24 → 3** and the App-Checker type-equality error class was cleared.

### Canvas app — Richer Entra/Graph user + manager capture (`ManageUsers`)

`ManageUsers` now hydrates a full profile via `Office365Users.UserProfileV2` (display name, email, given name, department, job title, hire date, network account, combined address) and the manager chain via `Office365Users.ManagerV2` (name, email, department, job title, photo), plus the approver's identity. Values populate existing `DeskAccessControl` columns (no SharePoint schema change). Person search uses live Graph search.

### Canvas app — Connector cleanup & Power BI re-point

- The unused **Microsoft Teams** connection, data source, and WADL were removed.
- `Screen1`'s Power BI embed was re-pointed to a new workspace/dashboard/tile and re-enabled (`Visible: =false` removed).

### Canvas app — Classic → modern control modernization (app-wide)

Classic glyph icons migrated to the modern `icon` control, printable/phone screen layout templates were flattened, and the legacy `group` control was retired for `groupContainer`. Trade-off: modern controls each expect explicit accessibility properties, so App-Checker accessibility findings rose (see Known Issues).
