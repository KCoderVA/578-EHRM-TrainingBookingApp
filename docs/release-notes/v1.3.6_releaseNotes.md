# 578 EHRM Training App — Release Notes (v1.3.6)

- **Release date**: 2026-10-07
- **Release type**: Patch / Documentation. Adds a GitHub Pages project overview for leadership and implementing developers.
- **Previous release**: v1.3.5 (2026-09-29)
- **Canvas app component**: v1.3.5 (unchanged)
- **Power Automate**: `AppUserList` v0.1.1, `SendReminders` v0.2.0, `CreateBackups` v0.1.0, `parseTMSReportsToSharePoint` v1.0.0 (all unchanged)

---

## Executive Summary

v1.3.6 adds a **graphical project overview website** (`docs/index.html`, published through GitHub Pages). It gives directors and chiefs at other VA hospitals a one-page summary of what the 578 EHRM Training App does, what it costs (nothing beyond standard Microsoft 365), and how mature it is. It gives the developers who would import it a full technical map and a step-by-step import guide. Every figure on the page comes from the repository. The app, flows, and data are unchanged.

**4 distinct improvement areas** are documented below:

1. **Executive Overview**: KPI tiles, charts, value story, screenshots.
2. **Technical Implementation Guide**: architecture, data model, flows, import QuickStart.
3. **Roadmap, Governance & Evaluation**: timeline, known issues, adoption checklist.
4. **Pages hosting and documentation alignment**: `.nojekyll`, version bump, README/CHANGELOG/status updates.

### Documentation — Technical Implementation Guide (`docs/index.html`)

Developers assigned to copy the solution previously had to piece the picture together from five component READMEs. This chapter puts it on one page.

**Contents:**
- Architecture diagram and data-flow map (Canvas app → SharePoint/Outlook → Power Automate → Power BI).
- Component inventory and versions, repository tree, 20-screen inventory, 8-tier access matrix.
- SharePoint data model (6 read/write app lists, national read-only EHRM reference lists, TMS CSV), 4-flow table, connector matrix (standard connectors only).
- **Deployment QuickStart:** prerequisites, 8 import steps, and `pac` pack/unpack/export commands.
- ALM/versioning, CI workflow inventory, and a security/privacy snapshot.

### Repository — Pages hosting and documentation alignment

- **`docs/.nojekyll`** (new, empty) makes GitHub Pages serve `/docs` as static files, so Jekyll/Liquid cannot break the build on `{{…}}` template text.
- **Portable links:** all images and repo links use absolute public-mirror URLs, because Pages from `/docs` publishes only that folder. All 24 paths were checked against the tracked tree.
- **No external dependencies:** no CDN scripts or fonts, so the page loads on restricted VA networks. Includes high-contrast, print/PDF, and mobile layouts.
