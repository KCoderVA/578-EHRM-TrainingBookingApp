chore(scripts,alm): v0.3.5 — automated release workflow scripts, Copilot commit-prep prompt, v0.3.4 artifact rotation

## Context

This commit delivers the **578 EHRM Training & Booking App** repo's **v0.3.5** patch release — a developer-tooling and ALM infrastructure update that introduces a fully automated release lifecycle for VA GHES environments. The changes were developed directly in VS Code as PowerShell 7 scripts and a Copilot Chat prompt file; no Canvas app, Power Automate, or SharePoint components were modified. The two new scripts under `src/scripts/pwsh/` now replace the previously manual `docs/local/v6_manualRepoManagement.md` release workflow. This release also performs the routine post-release artifact rotation: the three v0.3.4 live release artifact `.md` files are removed from `docs/release-notes/` and replaced with fresh v0.3.5 template copies.

No component version advances in this release. Canvas app baseline remains v0.3.4; `AppUserList` flow baseline remains v0.1.0.

## What changed — scripts (src/scripts/pwsh/)

### enterpriseCommitGuide.ps1 — NEW
- Automates the complete release branch/commit/push/PR/checks/merge/sync cycle for VA GHES environments
- **Phase 1 — Prerequisites:** validates `.\VERSION` exists; resolves `$ReleaseVer`, `$ReleaseTag`, `$Branch` (`pr/release-vX.Y.Z`), `$CommitFile`, `$PrFile`, `$RnotesFile`; asserts all three release artifact files exist before proceeding; reads first line of `$CommitFile` as `$CommitTitle` and `$PrFile` as `$PrTitle`
- **Phase 2 — Branch & commit:** `git switch main` → `git pull --ff-only` → `git switch --force-create $Branch` → `git add --all` → `git commit -m $CommitTitle -m (Get-Content $CommitFile)` → `git push --set-upstream origin $Branch`
- **Phase 3 — PR lifecycle:** `gh pr create --draft` using resolved title and body file; polls `gh pr checks --watch`; marks ready with `gh pr ready`; merges with `gh pr merge --merge --delete-branch --admin`
- **Phase 4 — Sync:** `git switch main` → `git pull --ff-only` → `gh repo sync`; prints final `git status --short` for confirmation
- Error handling: `$ErrorActionPreference = 'Stop'` and `$PSNativeCommandUseErrorActionPreference = $true` — any failed git/gh command halts the script immediately
- Output helpers: `Step` (Cyan) and `Done` (Green) console functions for structured phase output
- Apache 2.0 license header; `#Requires -Version 7`

### postEnterpriseCommitArchival.ps1 — NEW
- Performs the three-step post-release artifact rotation: **Archive → Rename → Populate**
- **Phase 1 — Prerequisites:** validates `.\VERSION`, `.\docs\release-notes\`, and `.\docs\release-notes\releaseTemplates\` exist; creates `.\archive\docs\release-notes\` if absent
- **Phase 2 — Discovery:** scans `docs/release-notes/` (non-recursive) for files matching `*_commitMessage.md`, `*_pullRequest.md`, `*_releaseNotes.md`
- **Phase 3 — Archive:** copies each discovered live file to `.\archive\docs\release-notes\`; on name collision, appends `yyyy.MM.dd-HH.mm.ss` timestamp suffix before extension to avoid overwrite
- **Phase 4 — Rename:** strips the old version prefix (everything before the first `_`) and prepends the `$NextTag` read from `.\VERSION`; e.g., `v0.3.4_commitMessage.md` → `v0.3.5_commitMessage.md`
- **Phase 5 — Populate:** for each renamed file, resolves the matching template from `.\docs\release-notes\releaseTemplates\` using keyword matching (`commitMessage`/`commit_message`, `pullRequest`/`pull_request`, `releaseNotes`/`release_notes`); overwrites renamed file with fresh template content, leaving it ready-to-fill-in for the next cycle
- Output helpers: `Step` (Cyan), `Done` (Green), `Warn` (Yellow) console functions
- Apache 2.0 license header; `#Requires -Version 7`

## What changed — Copilot prompts (.github/prompts/)

### enterprisePrepareCommit.prompt.md — NEW
- New GitHub Copilot Chat prompt file (`.prompt.md` format) that acts as an AI-driven release documentation agent
- **Step 1:** reads `./VERSION`, constructs path `./docs/release-notes/v{VER}_commitMessage.md`, and reads it
- **Step 2:** checks for `{{` / `}}` placeholder brackets — stops if already populated, continues if placeholders found
- **Step 3:** runs `git status --short`, `git status --verbose`, `git diff HEAD`, `git diff --cached`, `git diff --stat HEAD`, `git log --oneline -5`; performs direct workspace file analysis (reads modified source files, CHANGELOG, PROJECT_STATUS, README); builds complete inventory of all pending changes
- **Step 4:** rewrites the commit message file, replacing all `{{PLACEHOLDER}}` values with concrete findings; enforces quality rules (no vague language, no invented details, before→after values, named identifiers)
- **Step 5:** inserts a new `## [{VERSION}] - {YYYY-MM-DD}` entry into `CHANGELOG.md` immediately after `## [Unreleased]`, using only sections with real content
- **Final report:** prints structured summary of version, commit title, change areas count, CHANGELOG insertion, and next-step instructions
