# PR: v0.3.5 — scripts,alm,prompts: automated release workflow scripts, four Copilot release-prep prompts, v0.3.4 artifact rotation

## PR Summary

This PR delivers the **v0.3.5** patch release of the **EHRM Training & Booking App** — a developer-tooling and ALM infrastructure update that introduces a fully automated release lifecycle for VA GHES environments. Two new PowerShell 7 scripts (`enterpriseCommitGuide.ps1` and `postEnterpriseCommitArchival.ps1`) replace the previously manual step-by-step release workflow documented in `docs/local/v6_manualRepoManagement.md`, and four new Copilot Chat prompt files under `.github/prompts/` provide AI-assisted release documentation generation at every stage of the release cycle. No Canvas app, Power Automate, or SharePoint components were modified in this release.

This PR also performs the routine post-release artifact rotation: the three v0.3.4 live release artifact `.md` files are deleted from `docs/release-notes/` and replaced with fresh v0.3.5 template copies.

## Developer Tooling & ALM changes — detailed breakdown

### 1. PowerShell Release Automation Scripts (src/scripts/pwsh/)

Two new PowerShell 7 scripts deliver a fully automated release lifecycle for VA GHES environments, replacing the previously manual `docs/local/v6_manualRepoManagement.md` workflow guide.

**`enterpriseCommitGuide.ps1`** automates the complete branch/commit/push/PR/checks/merge/sync cycle:

- **Phase 1 — Prerequisites:** validates `.\VERSION` exists; resolves `$ReleaseVer`, `$ReleaseTag`, `$Branch` (`pr/release-vX.Y.Z`), `$CommitFile`, `$PrFile`, `$RnotesFile`; asserts all three release artifact `.md` files exist before proceeding; reads first line of `$CommitFile` as `$CommitTitle` and first line of `$PrFile` as `$PrTitle`
- **Phase 2 — Branch & commit:** `git switch main` → `git pull --ff-only` → `git switch --force-create $Branch` → `git add --all` → `git commit -m $CommitTitle -m (Get-Content $CommitFile)` → `git push --set-upstream origin $Branch`
- **Phase 3 — PR lifecycle:** `gh pr create --draft` using resolved title and body file; polls `gh pr checks --watch`; marks ready with `gh pr ready`; merges with `gh pr merge --merge --delete-branch --admin`
- **Phase 4 — Sync:** `git switch main` → `git pull --ff-only` → `gh repo sync`; prints final `git status --short` for confirmation
- Error handling: `$ErrorActionPreference = 'Stop'` and `$PSNativeCommandUseErrorActionPreference = $true` — any failed git/gh command halts the script immediately
- Output helpers: `Step` (Cyan) and `Done` (Green) console functions for structured phase output
- Apache 2.0 license header; `#Requires -Version 7`

**`postEnterpriseCommitArchival.ps1`** performs the three-step post-release artifact rotation:

- **Phase 2 — Discovery:** scans `docs/release-notes/` (non-recursive) for files matching `*_commitMessage.md`, `*_pullRequest.md`, `*_releaseNotes.md`
- **Phase 3 — Archive:** copies each discovered live file to `.\archive\docs\release-notes\`; on name collision, appends `yyyy.MM.dd-HH.mm.ss` timestamp suffix before extension to avoid overwrite
- **Phase 4 — Rename:** strips the old version prefix (everything before the first `_`) and prepends the `$NextTag` read from `.\VERSION`; e.g., `v0.3.4_commitMessage.md` → `v0.3.5_commitMessage.md`
- **Phase 5 — Populate:** for each renamed file, resolves the matching template from `.\docs\release-notes\releaseTemplates\` using keyword matching (`commitMessage`/`commit_message`, `pullRequest`/`pull_request`, `releaseNotes`/`release_notes`); overwrites renamed file with fresh template content
- Output helpers: `Step` (Cyan), `Done` (Green), `Warn` (Yellow) console functions
- Apache 2.0 license header; `#Requires -Version 7`

### 2. Copilot Chat Release Documentation Prompts (.github/prompts/)

Four new Copilot Chat prompt files (`.prompt.md` format) provide AI-assisted release documentation generation. Each prompt file acts as an autonomous release documentation agent within VS Code Copilot Chat:

- **`enterprisePrepareAll.prompt.md`** — Comprehensive single-pass agent: reads `VERSION`, checks all three release artifact files for `{{`/`}}` placeholders, runs `git status/diff/log` commands, performs direct workspace file analysis (reads modified source files, CHANGELOG, PROJECT_STATUS, README), populates all placeholder values in `_commitMessage.md`, `_pullRequest.md`, and `_releaseNotes.md`, inserts a new `CHANGELOG.md` entry, and prints a structured completion summary.
- **`enterprisePrepareCommit.prompt.md`** — Targeted agent scoped to the commit message artifact (`_commitMessage.md`) and CHANGELOG entry. Same git/workspace analysis workflow but produces only the commit message output.
- **`enterprisePreparePR.prompt.md`** — Targeted agent scoped to the pull request artifact (`_pullRequest.md`) only.
- **`enterprisePrepareRelease.prompt.md`** — Targeted agent scoped to the release notes artifact (`_releaseNotes.md`) only.

### 3. Release Artifact Rotation (docs/release-notes/)

Routine post-release housekeeping: the three v0.3.4 live release artifact files are removed from `docs/release-notes/` and replaced with fresh v0.3.5 template copies. This rotation is now automatable via `postEnterpriseCommitArchival.ps1` for future releases.

- **Removed:** `v0.3.4_commitMessage.md`, `v0.3.4_pullRequest.md`, `v0.3.4_releaseNotes.md` — previously committed with the v0.3.4 release; no longer needed in the live `docs/release-notes/` folder
- **Added:** `v0.3.5_commitMessage.md` (populated), `v0.3.5_pullRequest.md` (this file, populated), `v0.3.5_releaseNotes.md` (populated)
