## Executive Summary

v0.3.5 is a pure developer-tooling and ALM infrastructure patch — no Canvas app, Power Automate, or SharePoint components were modified. This release introduces a fully automated release lifecycle for VA GHES environments: two new PowerShell 7 scripts replace the previously manual step-by-step release workflow, and four new Copilot Chat prompt files under `.github/prompts/` provide AI-assisted release documentation generation at every stage of the release cycle. End users of the EHRM Training & Booking application will see no functional changes; this release targets repository maintainers and release engineers only. This release also performs the routine v0.3.4→v0.3.5 artifact rotation.

3 distinct improvement areas were implemented and are documented in full below:

1. **PowerShell Release Automation** — two new scripts fully automate the branch/commit/push/PR/checks/merge/sync cycle and post-release artifact rotation
2. **Copilot Chat Release Documentation Prompts** — four new AI-agent prompt files for generating all release artifact documents
3. **Release Artifact Rotation** — v0.3.4 live artifacts removed from `docs/release-notes/`; fresh v0.3.5 template copies added and populated

## Changes

### Scripts — Enterprise Release Automation (src/scripts/pwsh/)

Prior to v0.3.5, the release process was driven by the manual `docs/local/v6_manualRepoManagement.md` step-by-step guide — a multi-page procedure requiring the developer to run individual git, gh, and pac commands in sequence. Two new PowerShell 7 scripts replace this entirely.

**How it works:**

`enterpriseCommitGuide.ps1` automates the full release branch/commit/push/PR/checks/merge/sync cycle for VA GHES environments:

| Phase | What it does |
|---|---|
| Phase 1 — Prerequisites | Validates `.\VERSION`; resolves release variables (`$ReleaseVer`, `$ReleaseTag`, `$Branch`); asserts all three release artifact `.md` files exist; reads commit title from `_commitMessage.md` line 1 |
| Phase 2 — Branch & commit | `git switch main` → `git pull --ff-only` → `git switch --force-create pr/release-vX.Y.Z` → `git add --all` → `git commit` → `git push --set-upstream origin` |
| Phase 3 — PR lifecycle | `gh pr create --draft`; polls `gh pr checks --watch`; `gh pr ready`; `gh pr merge --merge --delete-branch --admin` |
| Phase 4 — Sync | `git switch main` → `git pull --ff-only` → `gh repo sync`; final `git status --short` |

`postEnterpriseCommitArchival.ps1` performs the three-step post-release artifact rotation:

| Phase | What it does |
|---|---|
| Phase 2 — Discovery | Scans `docs/release-notes/` (non-recursive) for `*_commitMessage.md`, `*_pullRequest.md`, `*_releaseNotes.md` |
| Phase 3 — Archive | Copies live files to `.\archive\docs\release-notes\`; timestamp suffix on collision |
| Phase 4 — Rename | Strips old version prefix; prepends next version from `.\VERSION` |
| Phase 5 — Populate | Overwrites renamed files with matching template content from `.\docs\release-notes\releaseTemplates\` |

Both scripts include: `$ErrorActionPreference = 'Stop'`; `$PSNativeCommandUseErrorActionPreference = $true`; `Step`/`Done`/`Warn` console output helpers; Apache 2.0 license header; `#Requires -Version 7`.

### Copilot Prompts — AI-Assisted Release Documentation (.github/prompts/)

Prior to v0.3.5, release artifact documents (`_commitMessage.md`, `_pullRequest.md`, `_releaseNotes.md`) were populated manually by the developer. Four new Copilot Chat prompt files automate this documentation work.

**How it works:**

Each prompt file (`.prompt.md` format) acts as an autonomous VS Code Copilot Chat agent that reads the current workspace state and populates release documentation:

| File | Scope |
|---|---|
| `enterprisePrepareAll.prompt.md` | All three artifacts + CHANGELOG in a single pass; checks for placeholders in each file; skips already-populated documents |
| `enterprisePrepareCommit.prompt.md` | Commit message artifact (`_commitMessage.md`) + CHANGELOG entry |
| `enterprisePreparePR.prompt.md` | Pull request artifact (`_pullRequest.md`) only |
| `enterprisePrepareRelease.prompt.md` | Release notes artifact (`_releaseNotes.md`) only |

All four prompts share the same core analysis workflow: read `VERSION`, run `git status/diff/log` commands, read modified source files and key project documents (CHANGELOG, PROJECT_STATUS, README), build a complete inventory of all pending changes, determine release type, then populate document placeholders with verified findings. No invented details; every populated field is traceable to the git diff or file content.
