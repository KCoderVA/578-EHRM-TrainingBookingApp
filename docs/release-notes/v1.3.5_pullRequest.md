# PR: v1.3.5 — Canvas app: MasterScheduleList scheduling migration, Success binding-error fix (24→3), richer user capture, Teams connector removed

## PR Summary

All project documentation has been updated end-to-end to reflect the new version.

The Canvas app component version advances from **v1.1.20 → v1.3.5**, now aligned with the project-wide SemVer release version.

## Canvas app changes — detailed breakdown

### 1. Supervisor scheduling re-based on `MasterScheduleList` (`POCSUPERVISOR`)

The supervisor screen's role / scenario / date-time pickers were moved off the national `Learning Lab Sessions` SharePoint list onto the app-owned `MasterScheduleList`, using stable `_text` columns (`RoleName_text`, `ScenarioName_text`, `TrainingCombinedDateTime_text`, `LocationCombined_text`) and an active-session filter (`sessionActive_text` blank or ≠ `"false"`). Legacy queries are commented out in place for auditability. A new button, `btn_patchMasterScheduleList_scenarioDescription_multitext`, back-fills the new `scenarioDescription_multitext` column.

> **Admin action required before deploying:** ensure the live `MasterScheduleList` includes the new `scenarioDescription_multitext` column and the `_text` scheduling columns before this release is used in production.

### 2. `Success` status-summary fix — 24 → 3 binding errors (closes v1.1.20 KI-02)

The `Success` screen was reworked to the current tier-flag model (`varDetailedListPatchOK`, `varFallbackOK`, `varSimpleListPatchOK`, `varEmailOK`), with the SuperUser-patch line gated by `user_IsSuperUser` and an email-notification status line added. `CanvasManifest.BindingErrorCount` dropped **24 → 3** and the App-Checker type-equality error class was cleared.

- Variables referenced were all pre-existing in v1.1.20 — this is a display-logic correction, not new state.
- Three residual binding errors remain (tracked as KI-01).

### 3. Richer Entra/Graph user + manager capture (`ManageUsers`)

`ManageUsers` now hydrates a full profile via `Office365Users.UserProfileV2` (display name, email, given name, department, job title, hire date, network account, combined address) and the manager chain via `Office365Users.ManagerV2` (name, email, department, job title, photo), plus the approver's identity. Values populate **existing** `DeskAccessControl` columns (no schema change). Person search moved to live Graph search.

### 4. Connector cleanup, Power BI re-point, and app-wide modernization

- **Microsoft Teams connector removed** (unused placeholder from v1.1.20 — closes KI-03).
- **`Screen1` Power BI** dashboard/tile/workspace re-pointed to a new report and re-enabled (`Visible: =false` removed).
- **App-wide:** classic glyph icons → modern `icon`; printable/phone screen layout templates flattened; legacy `group` control retired; modern-control default-property serialization; `ZIndex` renumbering.
- **App/other:** `App.OnStart` impersonation gate hardened to `Lower(User().Email)`; `Dashboard` dropped a deprecated `Refresh('Learning Lab Sessions')`; `DebuggingScreen` re-pointed two cards to `Description_multilinePlainText`; `chkWeekDays` recurrence caps refined.

- **SharePoint schema drift (KI-08):** `scenarioDescription_multitext` and `sessionActive_text` are not yet in the extracted schema under `src/sharePoint/`; re-extract in a follow-up.
