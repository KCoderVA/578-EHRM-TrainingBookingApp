# SharePoint — Difference Analysis `v0.12.2 → v1.0.12`

> **Audience:** the app owner and future maintainers.
> **Method:** current `src/sharePoint/` (working tree) vs. the archived v0.12.4 snapshot
> (`archive/src/sharePoint/v0.12.x/v0.12.4/`), plus cross-reference to the canvas-app data-model findings
> in [`../powerApps/v1.0.12_differenceAnalysis.md`](../powerApps/v1.0.12_differenceAnalysis.md) §6.

## Summary

The **schema of the app's own lists is stable** across this release (the canvas app simply began using
columns that already existed). The visible change here is a **structural reorganization and a major
expansion of the *reference-data* surface**: the folder was regrouped into a `nationalEHRM/sandbox/`
namespace, six national EHRM lists were added as tracked `*.url` shortcuts, and new folders were created
for the `MasterScheduleList`, `SuperUserList`, and `backupList_DeskReservations` app lists.

## 1. Two-environment architecture (made explicit at v1.0.12)

has `Role` choice; `Service Line - Sandbox` has `ServiceExamples`).

## 4. App list schema — stable
Per the canvas-app analysis, `Desks` (`ItemType_text`, `LocationMap_image`, `FloorNumber_number`,
`BuldingNumber_number`, `RoomNumber_number`, `DeskNumber_number`) and `Desk Reservations`
(`reservationDescription_multilinetext`, `DeskText`, `reservationDivision_text`,
`reservationAgreementBody_multilinetext`) **already contained** the columns the v1.0.12 app uses. No
list schema changes were required for this release.

## 5. Gaps / follow-ups
- **`searchConfig/SearchConfiguration.xml` restored** — the valid baseline search-schema export is back in
  place (the search schema itself is not customized; capture any custom managed properties via a real
  SharePoint Search Schema export when needed).
- **Large local export (by design):** `library/nationalEHRM/sandbox/learningLabLibrary/local/OneDrive_1_8-21-2026.zip`
  is **≈6.6 GB**. It is git-ignored (won't publish) and is intentionally retained as developer-only content.
- **`local/` data hygiene** — the CSV/XLSX exports contain real VA roster/scheduling data; they are
  git-ignored by folder and extension, but confirm none are force-added before any commit.
- **Reference-data coupling** — the app and Power BI now depend on the national `vacoehrmioeue/Sandbox`
  lists. Another hospital importing this solution must either gain read access to those lists or substitute
  their own equivalents.
