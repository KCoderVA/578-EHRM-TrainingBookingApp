# `parseTMSReportsToSharePoint` Deep-Dive Analysis (v1.2.7)

## Executive assessment

The flow establishes a useful automated ingestion bridge from a recurring TMS email report to the
stable SharePoint CSV consumed by the 578 EHRM Training Details Power BI report. Its production data
movement is straightforward: retrieve each matching attachment and write the original bytes to one
canonical file while creating an archive copy.

The current implementation should be described as **attachment ingestion with preliminary CSV
inspection**, not as a transformed CSV pipeline. The row-processing actions extract only the first
column (`Program ID`) into transient outputs that are never persisted or used to construct the
SharePoint file.

## Control-flow evaluation

### Trigger

`OnNewEmailV3` monitors messages addressed to the configured maintainer mailbox, accepts only the TMS
sender, includes attachments, and requires at least one attachment. There is no subject or expected
filename filter.

### Attachment branch

The top-level attachment loop executes after array initialization. Inside it, a condition accepts exact
lowercase `.csv` suffixes. For accepted files, `GetAttachment_V2` retrieves the attachment once, after
which these independent SharePoint writes can run:

- `UpdateFile` replaces `TMSProgramCompletion_DetailedReport.csv`.
- `CreateFile` writes the same bytes to the archive folder.

Because both actions depend only on attachment retrieval, archive failure does not inherently prevent
the canonical update, and canonical-update failure does not inherently prevent archiving. However,
there is no downstream scope that consolidates these outcomes or alerts an operator.

### Parsing branch

After the condition completes, the flow:

1. Base64-decodes `GetAttatchment.body.contentBytes`.
2. Splits text on line feed and skips the first line.
3. Splits each remaining line on commas.
4. Removes quotes from element 0.
5. Appends element 0 to `initializeArray`.
6. Creates a one-property `Program ID` mapping with `Select`.

Neither the array nor the Select result has a consumer. The branch is observational/development logic
rather than a completed business output.

## Data integrity findings

| Priority | Finding | Impact | Recommended correction |
|---|---|---|---|
| High | Sender is validated, but subject/report filename is not. | Any lowercase CSV sent by the trusted sender can replace the Power BI source. | Require the expected subject and attachment filename pattern. |
| High | Decode/parsing actions sit outside the condition's true branch. | A message with a non-CSV attachment can reference skipped `GetAttatchment` output and fail. | Move all attachment-dependent actions inside the true branch. |
| High | CSV parsing uses literal comma and line-feed splitting. | Quoted commas, CRLF edge cases, embedded line breaks, and escaped quotes can corrupt fields. | Use a standards-aware parser or leave parsing to Power Query. |
| High | No explicit catch/notification branch exists. | A failed update can leave Power BI serving stale data without an operator alert. | Add scoped run-after failure handling with an actionable notification. |
| Medium | Archive name uses unformatted `utcNow()`. | Colons in the generated name may cause SharePoint `CreateFile` rejection. | Use `yyyy-MM-dd_HHmmss` or another SharePoint-safe format. |
| Medium | `.csv` suffix check is case-sensitive. | Valid `.CSV` reports may be ignored and then trigger the skipped-output defect. | Compare `toLower(name)` with `.csv`. |
| Medium | Multiple CSV attachments target one canonical path. | Later loop iterations can overwrite earlier ones nondeterministically if concurrency is enabled. | Enforce one expected report per message and set loop concurrency deliberately. |
| Medium | The archive has no retention policy represented in source. | Employee training snapshots can accumulate indefinitely. | Apply retention, sensitivity, and least-privilege controls in SharePoint governance. |
| Low | Action names contain `Attatchment` misspellings and generic names (`Compose_2`, `Compose_3`, `Select`). | Run-history diagnosis and maintenance are harder. | Rename actions by business purpose during the next flow revision. |

## Operational dependencies

- The Outlook connection must read the configured recipient mailbox and download attachments.
- The SharePoint connection must update the existing canonical file and create files in the archive.
- The canonical file must already exist for `UpdateFile`.
- TMS must preserve the agreed sender identity and CSV schema.
- Power BI must retain access to the SharePoint file and run its own scheduled refresh.
- SharePoint and Power BI permissions must protect employee training records from unauthorized access.

## Recommended acceptance tests

| Test | Expected result |
|---|---|
| Expected message with one lowercase `.csv` | Canonical file replaced, one archive created, run succeeds. |
| Expected message with uppercase `.CSV` | Should process after hardening; current export does not match it. |
| Message with PDF only | Should exit cleanly; current export risks a skipped-action reference failure. |
| Message with two CSVs | Should reject ambiguity or select the named report deterministically. |
| Empty CSV | Should reject and notify rather than publish `NULL`/empty data. |
| CSV with quoted commas/newlines | Raw-copy path should remain byte-identical; parsed fields require parser validation. |
| Missing canonical file | Should alert with remediation; current `UpdateFile` cannot create it. |
| Archive folder unavailable | Canonical update outcome and archive failure should both be reported. |
| SharePoint throttling/connector expiry | Retry policy and operator alert should be verified in run history. |
| Power BI refresh after update | Dataset refresh completes and expected row/status totals reconcile to TMS. |

## Release recommendation

The flow is suitable to document and source-control in v1.2.7 as the initial automated ingestion
baseline, provided release notes explicitly identify the current parsing boundary and operational
prerequisites. Before treating it as unattended production-grade ingestion, address the high-priority
filename validation, condition scope, and failure-alerting findings and verify the archive filename in a
live run.
