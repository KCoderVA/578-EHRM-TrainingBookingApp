## 1. `AppUserList` — unchanged

Restored byte-for-byte identical to the committed version (no diff). For reference, its behavior:
SharePoint trigger on new `DeskAccessControl` items (poll 5 min) → `GetUserProfile` → branch by
`AccessLevel_Text`:
- **`AppAdmin`** → chatbot admin notice + email;
- enrich user & manager demographics (`ApplyToEach` over business phones, `Compose`, `UpdateItem`);
- **`User`** → chatbot admin notice + **`postAdaptiveCard` (wait-for-response webhook)** + 180 s delay;
- **advanced roles** (not `AccessDenied`/`View-only`/`User`/`AppAdmin`) → chatbot + email;
- **`AccessDenied` / `View-only`** → chatbot + adaptive card + `UpdateItem`;
- final confirmation email.

This flow contains the program's **"AI safety chatbot"** adaptive-card interactions
(`sendAdminChat`, `postAdaptiveCard`).

## 2. `SendReminders` — updated (`578EHRMTrainingApp_SendEmailReminder`)

**Trigger:** SharePoint `GetOnNewItems` on list `b7c9bc66…` — **polling changed from every 1 minute →
every 5 minutes.**

### Action-tree diff

| | OLD (v0.12.3) | NEW (v1.0.12) |
|---|---|---|
| Compose body | `cmp_Style/Greeting/EventDetails/Prereqs/Footer/FullBody` | *(same)* |
| Send email | `Send_an_email_(V2)` (unconditional) | **inside `Condition (CreatedBy = "Kyle.Coder")`** |
| Update item | `Update_item` after email | `Update_item` **before** notifications |
| Teams | — | **`Post_card_in_a_chat_or_channel` ×2 (adaptive cards)** |
| Test/diagnostic | `test(cmp_SendTime)`, `test(cmp_MinutesUntilSend)`, `cond_ShouldWait_1 → Delay_Until_2` | wrapped inside a `Condition (CreatedBy = "Kyle.Coder")` diagnostic branch |

### Functional changes
1. **Teams adaptive-card delivery added** — the reminder is now posted to Teams (twice) in addition to email.
2. **Email send gated** by a `CreatedBy = "Kyle.Coder"` condition — **intentional by design**: items the
   developer submits are handled differently from live end-user submissions, so email reminders fire only
   for the developer's own records.
3. **Reduced polling** (1 → 5 min) to cut API calls / throttling.
4. **Re-ordered** so `Update_item` (mark reminded) runs before the notification steps.

## 3. `CreateBackups` — new (`578EHRMTrainingApp_CreateBackupReservation`)

A brand-new flow with **no prior version**.

- **Trigger:** Outlook `OnNewEmailV3`, subject filter `[REGISTERED] EHRM Learning Lab Training -` — i.e.
  it fires off the confirmation email produced by the canvas app's `Confirm` screen. This is the primary
  **app → flow integration point** (there is no direct `.Run()` call from the app).
- **Body parsing:** ~19 `Compose` steps extract `Scenario`, `Role`, `TrainingDate`, `TrainingTime`,
  `LocationRaw`, `RoomNumber`, `FloorNumber`, `BuildingNumber`, `Division`, `RegistrationID`, start/end
  date-times (local + UTC), and a display range.
- **Enrichment:** `Get_user_profile_(V2)` + `Get_manager_(V2)`.
- **Write:** `Create_item` into backup list `593e180b…` on `…/578_EHRM_TrainingApp`, with
  `Title = "{RegistrationID} - {from} - Super User Learning Lab - {Scenario}"`.
- **Why it exists:** provides a redundant, email-sourced copy of every registration (resilience against a
  failed in-app SharePoint write, plus a cross-checkable audit trail).

## 4. Follow-ups
- **`SendReminders` email gate (intentional)** — the `CreatedBy = "Kyle.Coder"` condition is by design:
  developer-submitted items behave differently from live end-user submissions, so email reminders fire only
  for the developer's own records.
- **Artifact naming** — the packaged `.zip` exports are named `v1.0.12_*`, matching the public release.
- **Sanitization** — all three definitions embed environment-specific site URLs, list GUIDs, Teams
  recipients, and the email subject contract; re-point before deploying elsewhere.
