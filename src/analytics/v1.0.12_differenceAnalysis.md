## 1. Power BI — `Signup Tool`
Retained as the tracked `.pbit` template. It is an **identity-aware self-service report**: 40-table model
sourced from SharePoint (Super User roster `URAChicagoRaw/SU` on `…/VACO.OEHRMvisn/SitesDeploy`; scenarios
on `…/vacoehrmioeue/Sandbox`) and Excel schedule/seat workbooks (`…/vhachsfehrm/superusers`). Row-level
DAX (`USERPRINCIPALNAME()`, `IsCurrentUserEmailMatch`, `IsRoleMatch`) restricts what each signed-in Super
User sees. Six pages (`Diagnostics`, `SU Learning Lab - For Me / Someone Else / Search`,
`Scenario Description`, `Sign-Up App`). See [`powerBI/README.md`](powerBI/README.md).

## 2. Power BI — `SuperUserDashboard-Final` (new)
A **new leadership dashboard**, built as a **thin report on a published dataset**
(`DatasetId 3c9a5dc7-14b0-4e79-9e9b-926eeb800fd1`) rather than an embedded model. Pages: `Coming Soon`,
`Hines EHRM Super Users`, `HinesSuperUserOnlyDashboard` (slicers, cards, column/bar charts, detail tables).
**Work-in-progress.**

## 3. `tms/` data staging (new)
New folder ingesting VA **TMS** completion exports (`Incomplete 200 Level CBTs Detail`,
`Super User Program Completion Detail`) plus Power BI report links, feeding Super User training-progress
reporting. All data files git-ignored. See [`tms/README.md`](tms/README.md).

## 4. Integration with the rest of the solution
- The canvas app's new **`Screen1`** embeds a GOV-cloud Power BI tile (a print surface), tying the app to
  this reporting layer for the first time.
- The reports and the app both consume the national **`vacoehrmioeue/Sandbox`** reference lists — see
  [`../sharePoint/v1.0.12_differenceAnalysis.md`](../sharePoint/v1.0.12_differenceAnalysis.md).
