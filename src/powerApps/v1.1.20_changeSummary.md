## Executive summary

v1.1.20 is a **significant Canvas-app reliability and usability release** (a `1.0 → 1.1` minor-version jump that bundles a large body of hands-on editor work). There are **no new screens and no removed screens**, and the only schema touch is one new column referenced by the app. The centerpiece is a **re-architected booking-commit flow** on the `Confirm` screen: the old single, monolithic "Submit" button was replaced by a **thin orchestrator** that fires purpose-built child buttons (post calendar → patch reservation → sync Super User → send email) and then uses a **navigation timer** to verify that every step actually succeeded before showing the Success screen. Supporting this, the reservation write now uses a **tiered fallback cascade** that always writes to both the primary and backup SharePoint lists and degrades gracefully. The in-app **Help screen was rebuilt** from stale text into a friendly 10-step Quick-Start guide (with a full changelog view for admins), and the **class/scenario picker** was re-pointed to Hines-scoped in-memory collections with a new active-session filter. This release documents **7 functional areas** below. The one open functional defect is a **binding-error regression (0 → 24) on the `Success` screen**, which the developer will correct in a follow-up patch (see [`v1.1.20_knownIssues.md`](v1.1.20_knownIssues.md) KI-02).

**7 functional areas in this release:**

1. **Resilient booking-commit orchestration** — `Confirm` submit split into chained buttons + verification timer.
2. **Tiered both-lists fallback cascade** — every reservation write hits primary + backup, with graceful degradation.
3. **Rebuilt Help screen** — end-user Quick-Start guide + admin changelog viewer.
4. **Smarter class/scenario picker** — Hines-scoped collections, active-session filtering, cascade resets.
5. **New `sessionActive_text` reference** — lets staff avoid booking inactive sessions.
6. **Naming-convention & maintainability cleanup** — `btnOutlook_*` / `btnPatch_*` / `timer_*` control renames + email `Cc` fix.
7. **Experimental Screen1 data-explorer** — Power BI tile hidden; side-by-side session/schedule browse galleries (dev/admin, not yet on the menu).

## Functional impact & design rationale

### 1. Resilient booking-commit orchestration (`Confirm`)

**Before:** one large `btnSubmit` did everything inline — post the Outlook calendar item, patch the SharePoint reservation, sync the Super User list, send the confirmation email — and then navigated straight to Success. A silent failure could still land the user on "Success" with an incomplete booking.

**After:** `btnSubmit` is a lightweight orchestrator. It `Select()`s each dedicated child button in sequence, each recording a success flag (`varCalendarOK`, `varEmailOK`, `varPatchSuperUsersOK`, `varAnyListPatchOK`). A new **`timer_selectBtnsThenNavigate`** rolls those flags into `varAllOK` and only then performs `Navigate(Success)`, with a grace delay so notifications render (**2 s** success / **8 s** failure / **12 s** debug).

**Why it matters:** booking is the app's single most important transaction. Decoupling "do the work" from "declare success and leave" makes the outcome observable and far less likely to strand a user (or a proxy-registered student) with a half-written reservation.

### 2. Tiered both-lists fallback cascade (`Confirm`)

The reservation write is now a **four-tier cascade**, and every tier writes to **both** `'Desk Reservations'` (primary) and `backupList_DeskReservations` (backup):

| Tier | Button | Behavior |
|---|---|---|
| 1 | `btnPatch_detailedPrimary` | Full detailed record to both lists. |
| 2 | `btnPatch_detailedSecondary` | Detailed retry to both lists (on tier-1 failure). |
| 3 | `btnPatch_simplePrimary` | Simplified column set to both lists (on tier-2 failure). |
| 4 | `btnPatch_debugSimplified` | Writes tagged `"DEBUG …"` rows + raises an error notification (last resort). |

Success at each tier is measured per result-collection (`CountRows > 0 And CountIf(Not(ok)) = 0`), and a per-submission `varSubmissionID` (GUID) tags the rows for traceability.

**Why it matters:** SharePoint writes can partially fail under load/throttling. Always mirroring to backup and degrading through simpler writes maximizes the chance a durable record exists.

> **Design note (KI-08):** the debug tier writes rows literally prefixed `"DEBUG …"` into the **production** `'Desk Reservations'` list. Useful for diagnosis, but a roadmap item recommends routing these to a diagnostics list.

### 3. Rebuilt Help screen (`ReleaseNotes`)

Two audience-specific HTML views, shown mutually exclusively based on `user_isAdmin`:

- **End users** see **`htmlText_userGuide`** — a friendly, color-coded **10-step Quick-Start guide** through Home → who it's for → pick details → accept terms → review → submit → confirmation → return home, plus "Handy tips."
- **Admins** see **`htmlText_releaseNotes`** — a formatted render of the full project changelog.

**Why it matters:** the Help screen is the only in-product documentation for ~100–150 hospital staff. A task-oriented walkthrough reduces support burden; the admin changelog gives power users release context. (This realizes the two `local/` design proposals drafted earlier.)

### 4. Smarter class/scenario picker (`POCSUPERVISOR`)

The cascading Role → Scenario → Date/Time → Location picker was re-pointed from live SharePoint list queries to the **Hines-scoped in-memory collections** (`col_nationalEHRMLearningLabSessions`, `col_MasterSchedule`) loaded at startup. It now filters to `Facility = "Hines"`, hides inactive sessions via the new `sessionActive_text` value (§5), applies consistent "…NOT LISTED!" placeholders, and **resets downstream selections** when Role or Scenario changes.

**Why it matters:** faster, more reliable pickers (in-memory vs. delegation-limited queries) and fewer "impossible combination" bookings from stale cascade state.

### 5. New `sessionActive_text` reference

The app now uses a `sessionActive_text` value on the schedule so a scheduled session can be switched off; the Date/Time picker treats a session as bookable when the value is blank or not `"false"`.

> **Deferred (KI-04):** this column is referenced by the **Canvas app** (in a `Patch()`/picker chain), but the newer SharePoint list schema under `src/sharePoint/` has **not yet been extracted** — the developer will download and commit the updated SharePoint content in a **future patch**. For production, the column must exist/be populated on the live `MasterScheduleList`.

### 6. Naming-convention & maintainability cleanup

Controls on `Confirm` were renamed to consistent, self-describing conventions — `btnOutlook_PostCalendarItem`, `btnOutlook_SendAsEmail`, `btnPatch_detailedPrimary/Secondary`, `btnPatch_simplePrimary`, `btnPatch_superUserList`, `timer_selectBtnsThenNavigate` — and `Dashboard`'s generic `Timer3` became `timer_loadGlobalVariables`. A latent bug in the confirmation email's `Cc` was fixed (the mistyped `varAttendees` → `var_Attendees`, so CC recipients now resolve). The legacy monolithic submit was retained as **disabled/commented `btnOldSubmit`** for reference.

> **By design (KI-05/06):** the three top-level PM/admin addresses (`Kyle.Coder@va.gov`, `Celina.Ceballo@va.gov`, `Amy.Garner2@va.gov`) are intentionally hard-coded so notifications always reach the owners even during a data-source/network problem.

### 7. Experimental Screen1 data-explorer (dev/admin, not yet live)

`Screen1` was changed from the standalone printable Power BI screen (embed now **hidden**) into an experimental **side-by-side browse view** comparing the national `Learning Lab Sessions` library against the local `MasterScheduleList`, with Role/Scenario dropdown filters. It is **not wired into the menu** and has a placeholder `Button1` labeled "Button" — treat it as work-in-progress (KI-07).
