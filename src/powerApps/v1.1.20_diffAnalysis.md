## 3. Per-screen change detail

### 3.1 `Confirm.fx.yaml` — booking-commit architecture refactor (the headline change)

The screen roughly doubled in line count (3,026 → 6,122 lines) but gained a **net of one control** (a timer). The change is an architectural refactor of the booking-commit path from a **monolithic `btnSubmit`** into a **thin orchestrator that chains `Select()` calls to purpose-built child buttons**, followed by **timer-driven navigation**.

**Control inventory changes** (all inside the admin-only `ctn_Confirm_AdminButtons` container):

| Old control (As type) | New control (As type) | Change |
|---|---|---|
| `btnPostCalendarItem` As `button` | `btnOutlook_PostCalendarItem` As `button` | Rename; single responsibility (post + `Set(varCalendarOK,…)`) |
| `btnSendAsEmail` As `modernButton` | `btnOutlook_SendAsEmail` As `modernButton` | Rename; single responsibility (send + `Set(varEmailOK,…)`) |
| `btnPatchDetailedMainList` As `button` | `btnPatch_detailedPrimary` As `button` | Rename; cascade tier 1 |
| `btnPatchDetailedBackupList` As `button` | `btnPatch_detailedSecondary` As `button` | Rename; now writes **both** lists; cascade tier 2 |
| `btnPatchSimpleMainList` As `button` | `btnPatch_simplePrimary` As `button` | Rename; now writes **both** lists; cascade tier 3 |
| `btnPatchSuperUserList` As `modernButton` | `btnPatch_superUserList` As `modernButton` | Rename; logic unchanged (caption `"btnPatch_SuperUserList"` → `"Patch(superUserList)"`, `ZIndex` 7→8) |
| — | `timer_selectBtnsThenNavigate` As `timer` | **Added** — orchestration/navigation timer |
| — | `btnPatch_debugSimplified` As `button` | **Added** — debug/error-logging tier (cascade tier 4) |
| `btnPatchSimpleBackupList` As `button` | *(removed)* | Backup-only writes folded into the paired writes of every tier; slot repurposed for `btnPatch_debugSimplified` |
| `btnOldSubmit` As `button` | `btnOldSubmit` As `button` | **Preserved but fully disabled** — its ~439-line `OnSelect` body is wrapped in a `=/*… */` comment (dead code) |

**New orchestration timer — `timer_selectBtnsThenNavigate`:**

- `AutoStart: =If(var_timerPopUP_SubmitScreen = 0, false, var_timerPopUP_SubmitScreen > 0, true)`
- `Duration: =var_timerPopUP_SubmitScreen`
- Screen `OnHidden: =Set(var_timerPopUP_SubmitScreen, Blank());` (disarm on leave) — **new** (none in v1.0.12).
- Screen `OnVisible` gains a **STAGE 0 reset block** that pre-clears every new tier flag/collection to `Blank()` on each entry.
- `OnTimerEnd` computes rollup flags and navigates:

```powerfx
Set(varAllOK, false);
Set(varDetailedListPatchOK, If(varDetailedOK = true || varFallbackOK = true, true, false));
Set(varSimpleListPatchOK,   If(varMainSimpleOK = true, true, false));
Set(varAnyListPatchOK,      If(varDetailedListPatchOK = true || varSimpleListPatchOK = true, true, false));
Set(varAllOK, varCalendarOK And varEmailOK And varPatchSuperUsersOK And varAnyListPatchOK);
If(
    Lower(varRealEmail) = "kyle.coder@va.gov",
    Notify( Concatenate("varAllOK=", varAllOK, "; …") ),  // && Navigate(Success)  ← suppressed for this account
    Navigate(Success)
);
```

**Commit-flow change.** In v1.0.12, `btnSubmit` ran all work inline and called `Navigate(Success)` directly. In v1.1.20, `btnSubmit.OnSelect` performs **no navigation**; it chains `Select()` calls and then **arms the timer**:

```powerfx
// STAGE 8 — arm the timer instead of navigating
If(
    varDetailedListPatchOK = false, Set(var_timerPopUP_SubmitScreen, 8000),  // 8s grace on failure
    varDetailedListPatchOK = true,  Set(var_timerPopUP_SubmitScreen, 2000),  // 2s grace on success
    Navigate(Success)
);
```

Button-chaining sequence driven by the new `btnSubmit.OnSelect` (all former inline logic retained as comments):
1. `Select(btnOutlook_PostCalendarItem)` → `varCalendarOK`
2. `Select(btnPatch_detailedPrimary)` → begins the patch cascade
3. `Select(btnPatch_superUserList)` → `varPatchSuperUsersOK`
4. `Select(btnOutlook_SendAsEmail)` → `varEmailOK`
5. STAGE 8 arms timer → `OnTimerEnd` computes `varAllOK` → `Navigate(Success)`

**Tiered fallback cascade** — each tier now writes to **both** `'Desk Reservations'` (main) **and** `backupList_DeskReservations` (backup); success is computed per result-collection with `CountRows(col) > 0 And CountIf(col, Not(ok)) = 0`; on failure the tier `Select()`s the next tier:

| Tier | New button | Writes | Success flag | On failure → |
|---|---|---|---|---|
| 1 | `btnPatch_detailedPrimary` | main + backup (full record) | `varDetailedOK` | `btnPatch_detailedSecondary` |
| 2 | `btnPatch_detailedSecondary` | main + backup (detailed) | `varFallbackOK` | `btnPatch_simplePrimary` |
| 3 | `btnPatch_simplePrimary` | main + backup (simplified) | `varMainSimpleOK` | `btnPatch_debugSimplified` |
| 4 | `btnPatch_debugSimplified` | writes 2 **"DEBUG …"** rows to the **main** `'Desk Reservations'` list, tagged `OutlookSeriesID: varSubmissionID`; `Notify(…, Error, 5000)`; sets `var_timerPopUP_SubmitScreen, 12000` | `varDebugErr` | — |
| — | `btnPatch_superUserList` | `SuperUserList` row (`LearningLab_Scheduled_datetime`, `LearningLab_Class_datetime`, `LearningLab_ScenarioName`, `LearningLab_RoleName`, appends to `LearningLab_multiScenario_multipletext`) | `varPatchSuperUsersOK` | — (logic unchanged from v1.0.12) |

**New flag/collection model** replacing the old `varMainOK / varBackupOK / varBackupSimpleOK` axis: `varDetailedOK`, `varFallbackOK`, `varMainSimpleOK`, `varDetailedListPatchOK`, `varSimpleListPatchOK`, `varAnyListPatchOK`, `varAllOK`; new collections `colDetailedResults`, `colDetailedBackupResults`; new `varSubmissionID = Text(GUID())`. Error handling still uses `IfError(Patch(...), Set(flag,false), Set(flag,true))` / `!IsError(Patch(...))`-into-collection idioms; recurrence writes unchanged in shape (`ForAll(CollectionRecurrence …, ForAll(colSelectedDesks …))`).

**Outlook integration:**
- `btnOutlook_PostCalendarItem` (`Office365Outlook.V4CalendarPostItem`) — calendar **payload is byte-identical** to v1.0.12 (subject `"578 EHRM Learning Lab - " & var_reservationScenario`, `requiredAttendees/optionalAttendees: var_Attendees`, `body: var_EmailBody`, `location`, `importance:"high"`, `recurrence: varRecurrence`, `reminderMinutesBeforeStart: varReminder`, etc.). Only the surrounding orchestration was stripped out.
- `btnOutlook_SendAsEmail` (`Office365Outlook.SendEmailV2`) — subject and body unchanged; the **`Cc` list changed** (Old → New):
  - **Old:** `Cc: Concatenate(varAttendees, "; ")` — note the typo variable `varAttendees` (missing underscore).
  - **New:** `Cc: Concatenate(var_Attendees, "; ", varRealEmail, "; Celina.Ceballo@va.gov; Amy.Garner2@va.gov; ", varOptionalAttendees)` — typo fixed and now also CCs the submitter, two named staff addresses, and the optional attendees. (`Bcc: "Kyle.Coder@va.gov"`, `ReplyTo: "VHAHINInformaticsTrainingAndSupport@va.gov"` unchanged.)

**Other Confirm changes:** `HtmlText3.HtmlText` lost its outer `If(Parent.Visible = true, …)` guard (inner scenario-link `If` now evaluated unconditionally); `btnSubmit.FontWeight` `Semibold` → `Bold`; `ctn_Confirm_AdminButtons.Visible` remains admin-gated on `Lower(User().Email) = "kyle.coder@va.gov"`. The unchanged `Gallery3_1` review subtree and calendar payload are explicitly **not** part of this change.

### 3.3 `POCSUPERVISOR.fx.yaml` — class-picker re-sourcing (form churn is cosmetic)

The Edit form (`Form1`, DataSource `'Desk Reservations'`) contains the **same 13 typed data cards, same `DataField` bindings, no columns added/removed**. The very large `+/-` volume in the raw diff is **pure card-reordering realignment**: 8 of the 13 cards were reshuffled in tree order, which makes a line-based diff align *different* cards at the same offset. Per-card child-control numbers (`DataCardKey/Value/ErrorMessage/StarVisible`) are **identical** in both versions — no real renumbering occurred.

**Card order change (old pos → new pos):** `Reason for desk reservation` 5→12; `OptionalAttendees` 6→5; `Active_choice` 8→9; `RoomReservation` 9→11; `Title` 10→6; `Asset` 11→8; `Check Out From` 12→10. (Cards 1–4, 7, and 13 unchanged.) The controls flagged as "new" by a naïve diff (`OptionalAttendees_DataCard1`, `DateValue1`, `HourValue1`, `MinuteValue1`, `Separator2`) all **pre-exist in v1.0.12** and merely moved with their cards.

**The genuine functional changes are all in the `ctn_PopUp_ClassPicker` popup dropdowns:**

| Control / property | Old → New |
|---|---|
| `dropdown_RolePicker.Items` | Source `MasterScheduleList` (grouped `RoleName_text`) → `Filter(col_nationalEHRMLearningLabSessions, Facility.Value = "Hines")` (grouped `Role.Value`); keeps `["MY ROLE IS NOT LISTED!"]` placeholder. |
| `dropdown_ScenarioPicker.Items` | Source `'Learning Lab Sessions'` → `col_nationalEHRMLearningLabSessions` (grouped `Title`); both branches now wrapped in `Table(...)` and append `["MY SCENARIO IS NOT LISTED!"]`; returns only the placeholder when role = "MY ROLE IS NOT LISTED!". |
| `dropdown_DateTimePicker.Items` | Source `MasterScheduleList` → `col_MasterSchedule`; **adds active-session filter** `(IsBlank(sessionActive_text) \|\| sessionActive_text <> "false")` (uses the new column, §6) + "scenario not listed" guard. |

Net effect: the class picker now reads from the in-memory Hines-scoped collections (`col_nationalEHRMLearningLabSessions`, `col_MasterSchedule`) instead of live list queries, honors the new active-session flag, and resets downstream selections when Role/Scenario change.
