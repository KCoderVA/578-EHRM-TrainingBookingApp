## Detailed register

### KI-01 — `.msapp` package filename aligned to `v1.1.20` · Low · ALM/housekeeping · ✅ Resolved
**Evidence:** the packaged Canvas app committed under `src/powerApps/.msapp/` is named **`v1.1.20_578EHRMTrainingApp.msapp`**, matching the release. The app internally stamps `1.1.20` (`App.fx.yaml` `varRepoVersion`, `CanvasManifest.AppDescription`) and the `.zip` bundle is also `v1.1.20_…`.
**Resolution:** the previously-mislabeled `v1.0.15_…` package file was **renamed** to `v1.1.20_578EHRMTrainingApp.msapp` (the `.msapp` binary content was **not** modified — only the filename prefix). All documentation, `VERSION`, `solution.xml`, the `.zip`, and the `.msapp` now read `v1.1.20`.
**Note:** the earlier "version-string drift" concern is **fully resolved** — `v1.1.20` is the confirmed, consistent version everywhere. *(If you next re-export the app from the editor, keep the `v1.1.20_` filename prefix.)*

### KI-02 — 24 binding errors on the `Success` screen · High · bug · 🆕 (fix in follow-up patch)
**Root cause:** the `Confirm` booking-commit refactor (see diff analysis §3.1) **retired the old patch-flag variables** `varMainOK`, `varBackupOK`, and `varBackupSimpleOK` (replaced by the tier-flag model `varDetailedOK` / `varFallbackOK` / `varMainSimpleOK` / `varDetailedListPatchOK` / `varSimpleListPatchOK` / `varAnyListPatchOK` / `varAllOK`). The **`Success` screen was not updated to match**, so it still references the removed variables — producing 24 `High`-severity App Checker findings (this is exactly the `CanvasManifest.BindingErrorCount: 24`).

**Exact breakdown (from `Entropy/AppCheckerResult.sarif`, all on screen `Success`):**

| Location (control / property) | Rule | Count | Offending references |
|---|---|---:|---|
| `Success.OnVisible` | `app-ErrInvalidName` | 6 | `varMainOK` (×2), `varBackupOK` (×2), `varBackupSimpleOK` (×2) |
| `Success.OnVisible` | `app-ErrIncompatibleTypesForEquality-Left-Right` | 6 | `=` / `<>` comparisons that resolve to `Error` vs `Boolean` (because the vars above are now undefined) |
| `Success.LblSuccessMsg1_2.Text` | `app-ErrInvalidName` | 6 | `varMainOK` (×2), `varBackupOK` (×2), `varBackupSimpleOK` (×2) |
| `Success.LblSuccessMsg1_2.Text` | `app-ErrIncompatibleTypesForEquality-Left-Right` | 6 | `=` comparisons resolving to `Error` vs `Boolean` |
| **Total** | | **24** | |

**What to change in the editor (do NOT change now — planned follow-up patch):**
1. Open the **`Success`** screen.
2. In **`Success.OnVisible`** and in **`Success.LblSuccessMsg1_2.Text`**, find every reference to `varMainOK`, `varBackupOK`, and `varBackupSimpleOK`.
3. Replace them with the current tier flags — most likely:
   - `varMainOK` → `varDetailedListPatchOK` (or `varDetailedOK`)
   - `varBackupOK` → `varFallbackOK`
   - `varBackupSimpleOK` → `varSimpleListPatchOK` (or `varMainSimpleOK`)
   - and use `varAllOK` for the overall success message where appropriate.
4. Re-check App Checker — `BindingErrorCount` should return to `0`. The `app-ErrIncompatibleTypesForEquality` findings disappear automatically once the names resolve to Booleans again.
> The 4 additional `app-ErrOptionNotRecognized` findings and 1 lower-severity type finding are **Low/Medium** (not part of the 24 red binding errors) and can be reviewed separately.

### KI-03 — Microsoft Teams connector present but not yet wired up · Low · intentional placeholder · ✔️ Accepted
**Evidence:** `Connections/Connections.json` declares a Microsoft Teams connection (`33696c3a-…`, Standard); `DataSources/MicrosoftTeams.json` + `pkgs/Wadl/MicrosoftTeams.xml` present. No formula in `Src/**` references it.
**Status (per developer):** the Teams data connection was **added intentionally** as a placeholder; no code/function uses it yet, and it may be removed later. It is **not treated as a defect** for this release.
**Action taken this run:** the Teams reference has been **removed from `src/solution.xml`** (it does not functionally exist yet), so the solution manifest does not advertise a Teams dependency. The connection still exists in the app's own `Connections.json` (part of the read-only unpacked source, left untouched).

### KI-04 — `sessionActive_text` in the app, not yet in the extracted SharePoint schema · Medium · deferred · 🆕
**Evidence:** the Canvas app references `sessionActive_text` (in `POCSUPERVISOR` `dropdown_DateTimePicker.Items` and its `MasterScheduleList` data-source projection / table definition). The extracted SharePoint list documents under `src/sharePoint/` (schema/`.url`/CSV snapshots) do **not** yet include this column.
**Status (per developer):** intentional — the newer v1.1.20 SharePoint list content has **not been downloaded/extracted yet**; it will be added in a **future minor patch**. Proceeding with the v1.1.20 release without it is expected.
**Follow-up:** (a) ensure the column exists/is populated on the **live** `MasterScheduleList` (blank = active; `"false"` hides the session); (b) re-extract the SharePoint schema into `src/sharePoint/` in the next patch and update its README.

### KI-05 — Developer/admin email gates hard-coded in `Confirm` / `App` · Info · by design · ✔️ Accepted
**Evidence:** `Confirm` `timer_selectBtnsThenNavigate.OnTimerEnd` branches on `Lower(varRealEmail) = "kyle.coder@va.gov"` (shows a diagnostic `Notify` for that account); `ctn_Confirm_AdminButtons.Visible` gates on the same address; `App.OnStart` references it.
**Status (per developer):** intentional. These references are hard-coded for the top-level project owner/admin to guarantee the app keeps working even if a network or data-source problem occurs. **Kept by design.** *(Informational note for future maintainers: the developer account sees a diagnostic notification instead of auto-navigating to `Success` — this is deliberate debug behavior.)*

### KI-06 — Admin/PM email addresses hard-coded in confirmation-email `Cc` · Info · by design · ✔️ Accepted
**Evidence:** `Confirm` `btnOutlook_SendAsEmail` → `Cc: Concatenate(var_Attendees, "; ", varRealEmail, "; Celina.Ceballo@va.gov; Amy.Garner2@va.gov; ", varOptionalAttendees)`.
**Status (per developer):** intentional. `Kyle.Coder@va.gov`, `Celina.Ceballo@va.gov`, and `Amy.Garner2@va.gov` are the top-level project managers / app admins; they are hard-coded so notifications always reach them even if a data source is unavailable. **Kept by design.** (The v1.1.20 fix of the `varAttendees` → `var_Attendees` typo remains a genuine improvement — CC recipients now resolve.)

### KI-07 — `Screen1` experimental/incomplete · Medium · incomplete feature · ➡️ Carried (changed)
**Evidence:** `Src/Screen1.fx.yaml` — Power BI embed `Visible: =false`; new `Gallery7`/`Gallery8` browse galleries; placeholder `Button1` with `Text: ="Button"`; still absent from `App.OnStart` `colMenu`, no inbound `Navigate()`.
**Impact:** a half-built developer screen ships inside the package (no user entry point, so low direct risk; contributes untested controls).
**Suggested fix:** finish it behind an admin role (remove `Button1`), revert to the printable Power BI view, or remove it.

### KI-08 — Debug tier writes `"DEBUG …"` rows into production reservation list · Medium · data-integrity · 🆕
**Evidence:** `Confirm` `btnPatch_debugSimplified` `Patch`es rows titled `"DEBUG - … GUID: " & varSubmissionID` into `'Desk Reservations'` when all higher tiers fail.
**Impact:** last-resort diagnostics land in live data; may confuse reporting/Power BI.
**Suggested fix:** route to a diagnostics list (or `backupList_DeskReservations` with a flag), or gate behind a `varDebugMode`; exclude `"DEBUG"` rows from user-facing galleries/reports.

### KI-09 — Large commented-out dead code · Low · tech-debt · 🆕
**Evidence:** `Confirm` `btnOldSubmit.OnSelect` (~439 lines) fully commented; `btnSubmit` retains former inline copies as comments; `POCSUPERVISOR` picker `Items` retain legacy queries as `/*… */`.
**Suggested fix:** delete the commented blocks once the new flow is production-proven (history preserved in git + `archive/`).

### KI-10 — `HtmlText3` lost its `Parent.Visible` guard · Low · performance · 🆕
**Evidence:** `Confirm` `HtmlText3.HtmlText` — outer `If(Parent.Visible = true, …)` wrapper removed; inner scenario-link `If` now evaluated unconditionally.
**Suggested fix:** restore the `Parent.Visible` short-circuit if intentional (minor).

### KI-11 — `MyAppts` cancellation still stubbed · Medium · incomplete feature · ➡️ Carried
**Evidence:** `Src/MyAppts.fx.yaml` unchanged this cycle; the `Button3_9` ("Cancel This") stub noted in `docs/PROJECT_STATUS.md` remains.
**Suggested fix:** implement the cancel `Patch` (status/cancelled flag) with a confirmation prompt and optional notification.

### KI-12 — Environment-specific GUIDs / site URLs in tracked source · Low · accepted policy · ➡️ Carried
**Evidence:** unpacked `Src/**` contains tenant/environment GUIDs, SharePoint site URLs, and a Power BI GOV embed URL. (The VA email addresses in KI-05/06 are **intentional** and accepted.)
**Status:** the repo already publishes unpacked source with a sanitization note in `src/powerApps/README.md`; this remains a standing policy decision for the developer, not a v1.1.20 blocker.
