## 3. Per-screen / per-component changes

> **Reading note.** Across nearly every screen the newer authoring runtime emitted large volumes of modern-control default properties (`AutoHeight`, `Layout*`, `maximum*/minimum*`, `WidthFit`, `ContentLanguage`, `Font: =""`, `BorderStyle: =""`, `Size:`, `HintText:`, `#CopilotOverlayLabel: ="Filtered"`, `ChildTabPriority`, `EnableChildFocus`), migrated classic glyph icons (`icon.View`, `icon.ChevronRight`, …) to the modern `icon` control, flattened printable/phone **screen layout templates** to plain `screen`, and renumbered `ZIndex`. These are catalogued once in §7 and are **excluded** from the per-screen "genuine change" notes below.

### 3.1 `POCSUPERVISOR` — supervisor scheduling rework *(the centerpiece; +480 / −152 genuine lines)*

This proof-of-concept supervisor screen received the largest functional change in the release.

- **Data-source migration `Learning Lab Sessions` → `MasterScheduleList`.** The active scenario / role / date-time picker logic was moved off the national **`Learning Lab Sessions`** SharePoint list onto the app's own **`MasterScheduleList`**, using its text columns:
  - `RoleName_text` (replacing `Role.Value`),
  - `ScenarioName_text` (replacing `Title` / `Scenario.Value`),
  - `TrainingCombinedDateTime_text` (date-time picker source),
  - `LocationCombined_text`,
  - and an active-session filter `(IsBlank(ThisRecord.sessionActive_text) || ThisRecord.sessionActive_text <> "false")`.
  The legacy `Learning Lab Sessions` / `col_nationalEHRMLearningLabSessions` queries are now **commented out** in place rather than deleted (e.g. `//'Learning Lab Sessions',`, `//col_nationalEHRMLearningLabSessions,`, and a dated developer note `//////ATTN KYLE!  AS OF 09/23/2026:  Testing alternative formula`). *(String-count check: `col_MasterSchedule` already existed in v1.1.20 — this is a continuation/completion of an in-progress migration, not a from-scratch move.)*
- **New scenario-description back-fill tool.** A new modern button **`btn_patchMasterScheduleList_scenarioDescription_multitext`** (`Text: ="patch(MasterScheduleList_scenarioDescription_multitext)"`) collects `col_MasterSchedule` / `col_scenarioRowsToPatch`, computes `_desc: LookUp(…)`, filters rows where `IsBlank(scenarioDescription_multitext)` or `scenarioDescription_multitext <> _desc`, and `Patch`es `{scenarioDescription_multitext: _desc}` into `MasterScheduleList`. This is the in-app writer for the **new** `scenarioDescription_multitext` column (§4). `btn_patchMasterScheduleList…` = **0 matches in v1.1.20** (genuinely new).
- **People-picker rewrite to live Graph search.** The manager / reserved-by combobox moved from SharePoint choice columns (`Choices([@'Desk Reservations'].'Reserved By' / .Manager)`) to `Office365Users.SearchUserV2`, wrapped in a `With({targetProfile: If(…Office365Users.MyProfile()…)}, …)` that is impersonation-aware (uses `varTargetEmail` / `varTargetEntraID`, photo via `Office365Users.UserPhoto`). `DisplayFields`/`SearchFields` narrowed to `["Email","DisplayName","Picture"]` / `["Email"]`.
- **Scenario-name normalization** (`Substitute(...)` chains stripping `" - Day 1/2/3"`, `"Scenario 1/2/3 - "`, and abbreviating `"Residential Rehabilitation Treatment Program Admission"` → `"RRTP Admission"`, `"Revenue Utilization Review"` → `"RUR"`) was restructured to match against `ScenarioName_text`.

### 3.2 `ManageUsers` — expanded Entra / Graph profile capture *(+400 / −402 genuine lines)*

The admin "Manage Users" screen (editing `DeskAccessControl`) gained much richer identity capture:

- **Full profile from `Office365Users.UserProfileV2(varUserToEdit.Id_Text)`:** `DisplayName_Text`, `Email_Text` (`Lower(userPrincipalName)`), `GivenName_Text`, `Department_Text`, `JobTitle`, `HireDate_Text`, `MailNickname_Text` / `NetworkAccount_Text`, and a concatenated address (`streetAddress, city, state, postalCode, companyName`).
- **Manager chain via `Office365Users.ManagerV2(…)`:** `Manager_DisplayName_Text`, `Manager_Email_Text`, plus the manager's department / job title / photo.
- **Approver capture:** `Approver_DisplayName_Text` (`Office365Users.MyProfileV2().displayName`) and `Approver_Email_Text` (`varRealEmail`).
- **Graph people-picker:** `Search(Office365Users.SearchUserV2({searchTerm:Self.SearchText,top:15}).value, …, DisplayName, Mail, Surname, GivenName)` with `SearchFields: =["DisplayName","Mail","Surname","GivenName"]`.
- Supporting UI: `ClearCollect(colDeskAccess, DeskAccessControl)`, `Reset(Dropdown4)`, `Set(var_loading, true)`, and delete-confirmation controls.

These values are `Patch`ed into **existing** `DeskAccessControl` columns — the `DeskAccessControl` data source shows **no** schema change (only the `{IsFolder}` label refresh), so this is richer population of an existing schema, not new columns.

### 3.3 `DebuggingScreen` — field re-point (binding correction)

Two cards were re-pointed from `Description_multilineText` to **`Description_multilinePlainText`** on `[@Desks]` (`DisplayName` and `MaxLength` via `DataSourceInfo`). Both column names exist in both versions (old-vs-new counts: `…PlainText` 8 → 10, `…multilineText` 24 → 22), so this is a **binding correction on two cards**, not a column rename — consistent with the `BindingErrorCount` reduction. Everything else on this screen is modern-control default serialization (§7).

### 3.4 `Confirm` — no functional change

Despite its size, `Confirm` (the booking-commit orchestrator introduced in v1.1.20) changed by only **+3 / −1** genuine lines (a `ZIndex`, a `Size`, and a `#CopilotOverlayLabel: ="Filtered"`). The tiered fallback cascade, orchestrator button, and navigation timer are **unchanged**. The debug tier (`btnPatch_debugSimplified`, `"DEBUG …"` rows) and the commented `btnOldSubmit` block **still ship** (carried `KI-08` / `KI-09`).

### 3.5 `Success` — status-summary display reworked

The post-booking status summary was reworked to align with the v1.1.20 tier-flag model (this is the corrective work behind `BindingErrorCount 24 → 3`):

- List status lines were **re-labelled / re-mapped** to the current flags: `varDetailedListPatchOK` ("Main reservation list"), `varFallbackOK` ("Backup reservation list"), `varSimpleListPatchOK` ("Backup (simple) reservation list").
- A new **email-notification** status line uses `varEmailOK` / `varSimpleListPatchOK`.
- The **SuperUser-patch** status line is now gated by `If(user_IsSuperUser = true, …)`.
- Several legacy lines were commented out (`//If(varFallbackOK …)`, `//If(varPatchSuperUsersOK …)`).

All variables referenced here **pre-existed** in v1.1.20 (`varDetailedOK` 43→47, `varSimpleListPatchOK` 10→14, `varDetailedListPatchOK` 10→11, `varEmailOK` 24→22, `user_IsSuperUser` 17 present) — this is a **display-logic rework**, not new state.

### 3.6 `Dashboard` — deprecated-list refresh removed

`Refresh('Learning Lab Sessions');` was removed and replaced by the comment `//REMOVED depreciated SP List:  //Refresh('Learning Lab Sessions');`, consistent with the `Learning Lab Sessions` → `MasterScheduleList` deprecation in §3.1.

| `DashboardId` | `e948a0b5-96a3-43a5-a1b3-500c4fe926fa` | `5045c9a5-0716-4b59-9b14-4763d686ae44` |

### 3.8 `chkWeekDays` — recurrence cap logic refined

The recurrence engine's `maxOccurrence` calculation was tuned with `Min(...)` caps per frequency, e.g.:
- `"Weekly"` → `Set(maxOccurrence, Min(recurPeriodTxt_1.Text, RoundUp(26 / Value(recurPeriodTxt.Text), 0), 26))`
- `"Day"` (monthly) → `Set(maxOccurrence, Min(RoundUp(Min(6 / Value(recurPeriodMonthTxt.Text)), 0), Value(recurPeriodTxt_1.Text), 6))`

Some monthly branches were commented out (`///"Monthly", …`). The remainder of this component's very large positional churn (2,136+/2,004− raw) collapses to value tweaks across its many replicated controls plus modern-control serialization — no new feature.

### 3.9 `App` — impersonation gate hardened

- `varRepoVersion` `"1.1.20"` → `"1.3.5"`.
- Impersonation gate changed from `varTargetEmail = "kyle.coder@va.gov" && varRealEmail <> varTargetEmail` to **`Lower(User().Email) = "kyle.coder@va.gov" && varRealEmail <> Lower(User().Email)`** — evaluated against the live, case-insensitive signed-in identity rather than a mutable variable.
- A leftover commented test line was added: `//Set(varRealEmail, Lower("[REDACTED]@va.gov"));` (dead code containing a specific VA user's email — redacted here; see the `KI` register).

### 3.10 Other screens — modernization only

`DeskSelect`, `NewDesk`, `NewEditDesk`, `PDFScreen`, `MyAppts`, `scrn_DailyCal`, `scrn_WeeklyCal`, `scrn_MoCalendar`, `ManageDesks`, `Reservation`, `ReleaseNotes`, `SuccessDeskMod`, and the `Calendar` / `Tabs` / `Tabs_3` / `Preloader` components changed **only** through the platform patterns in §7 (icon modernization, template flattening, legacy `group` flattening, modern-control defaults, `ZIndex` renumbering, minor position tweaks). Notably, the cancellation-confirmation dialogs on `scrn_DailyCal` / `scrn_WeeklyCal` and the empty-state messages on `DeskSelect` **already existed** in v1.1.20 (verified) and are *not* new.

## 7. Platform-wide modernization patterns (low author-significance)

These recurring, tooling-driven patterns account for the bulk of the 155-file / high-line churn and are **not** developer feature changes:

1. **Classic → modern icon migration:** `X As icon.<Glyph>:` → `X As icon:` across virtually every screen (`icon.View`, `icon.ChevronRight`, `icon.ChevronLeft`, `icon.Cancel`, `icon.Print`, `icon.Home`, `icon.Add`, `icon.OpenInNewWindow`, `icon.Search`, `icon.CancelBadge`, `icon.GlobeRefresh`, `icon.HorizontalLine`, …). Side effect: classic-icon `Hover*/Pressed*/Disabled*` state-style bindings were dropped.
2. **Screen layout-template flattening:** `"X As screen.'printableLayout_A4Landscape_ver1.0'":` and `"X As screen.'phoneLayout_Success_ver3.0'":` → plain `X As screen:` (affects `PDFScreen`, `Screen1`, `Success`, `SuccessDeskMod`, `ReleaseNotes`).
3. **Legacy `group` control removal / flattening** (see §6).
4. **Modern-control default-property serialization:** bulk addition of `AutoHeight`, `BorderThickness`, `ContentLanguage`, `Layout{Height,Width,X,Y}`, `maximum/minimumHeight/Width`, `WidthFit`, `Font: =""`, `BorderStyle: =""`, `Size:`, `HintText:`, `FindText:`, `Password:`, `Required:`, `InputTextPlaceholder: ="Find items"`, `ChildTabPriority: =true`, `EnableChildFocus: =true`.
5. **Copilot overlay labels:** `'#CopilotOverlayLabel': ="Filtered"` added to gallery/filter controls by the newer Studio.
6. **`ZIndex` renumbering** across many containers (cosmetic ordering).
7. **Line-ending / whitespace normalization** across many `.json` files (byte-different, content-identical).
