## Short term — the planned follow-up patch (v1.1.21)

### R-01 · Fix the 24 `Success`-screen binding errors · Effort S–M · addresses KI-02
- **Rationale:** the top functional defect this cycle — `BindingErrorCount` regressed `0 → 24` because the `Success` screen still references the retired flag variables `varMainOK` / `varBackupOK` / `varBackupSimpleOK`.
- **Action:** in `Success.OnVisible` and `Success.LblSuccessMsg1_2.Text`, replace those with the new tier flags (`varDetailedListPatchOK` / `varFallbackOK` / `varSimpleListPatchOK` / `varAllOK`); re-verify App Checker returns `BindingErrorCount = 0`.
- **Expected impact:** removes all 24 red errors; correct Success messaging. **Dependencies:** none (self-contained on `Success`).

### R-02 · ✅ Done — `.msapp` package renamed to `v1.1.20` · addresses KI-01
- **Completed:** the mislabeled `v1.0.15_578EHRMTrainingApp.msapp` was renamed to `v1.1.20_578EHRMTrainingApp.msapp` (the `.msapp` binary content was not modified — only the filename prefix). Everything now reads `1.1.20` (docs, `VERSION`, `solution.xml`, `.zip`, internal `varRepoVersion`/`AppDescription`, and the `.msapp`).
- **If you re-export** from the editor in the future, keep the `v1.1.20_` filename prefix.

### R-03 · Extract & commit the updated SharePoint schema (`sessionActive_text`) · Effort S · addresses KI-04
- **Rationale:** the app references `MasterScheduleList.sessionActive_text`, but the SharePoint list snapshots under `src/sharePoint/` don't include it yet.
- **Action:** confirm/populate the column on the live `MasterScheduleList` (blank = active, `"false"` hides), then re-extract the schema into `src/sharePoint/` and update its README.
- **Expected impact:** the shipped picker filter works in production; source matches the app. **Dependencies:** SharePoint admin access.

## Medium term — next minor cycle (v1.2.0)

### R-04 · Decide the Microsoft Teams connector's long-term fate · Effort S–M · addresses KI-03
- **Rationale:** the Teams connection is an intentional placeholder in the app (and has been removed from `src/solution.xml` for now). It's either a future feature or dead weight.
- **Action:** either implement the intended Teams notification (e.g., post an adaptive card to the coordinators' Team/channel when a booking commits, `varAllOK = true`) — complementing the existing email + calendar invite — **or** remove the connection from the app's `Connections.json` on the next export.
- **Expected impact:** a real notification channel or a cleaner connector footprint. **Dependencies:** none.

### R-05 · Ship the `MyAppts` self-cancellation workflow · Effort M · addresses KI-11
- **Rationale:** users still cannot self-cancel (`Button3_9` "Cancel This" is a stub) — a long-standing carried gap.
- **Action:** implement the cancel `Patch` (status/cancelled flag), a confirmation prompt, and an optional cancellation email; make it series-vs-single aware to match the booking cascade.
- **Expected impact:** complete booking lifecycle; less admin overhead. **Dependencies:** SharePoint status column.

### R-06 · Resolve `Screen1` (finish, gate, or revert) · Effort M · addresses KI-07
- **Rationale:** a placeholder-laden dev screen ships unlinked in the package (contributed some of the churn this cycle).
- **Action:** finish the session-vs-schedule comparison behind an admin role (remove placeholder `Button1`), revert `Screen1` to the printable Power BI view, or remove it.
- **Expected impact:** no half-built UI in production; possible new admin reconciliation tool. **Dependencies:** none.

### R-07 · Keep the debug tier out of production data · Effort S · addresses KI-08
- **Rationale:** `"DEBUG …"` rows land in the live `'Desk Reservations'` list on total failure.
- **Action:** route debug writes to a dedicated diagnostics list (or flag + exclude from galleries/Power BI); gate behind a `varDebugMode`.
- **Expected impact:** clean reservation data and reporting. **Dependencies:** none.

### R-08 · Auto-sync the in-app admin changelog · Effort M
- **Rationale:** `htmlText_releaseNotes` embeds a point-in-time render of `CHANGELOG.md`; it will drift as the changelog grows.
- **Action:** add an ALM step/script to regenerate the HTML from `CHANGELOG.md` at release time, or source it from a SharePoint list a flow maintains.
- **Expected impact:** the admin changelog view stays accurate without manual edits. **Dependencies:** none.

### R-09 · Remove dead code after the new commit flow is proven · Effort S · addresses KI-09
- **Rationale:** the commented `btnOldSubmit` and inline copies roughly doubled the `Confirm` file size.
- **Action:** once the orchestration + cascade are production-validated, delete the `/* … */` legacy blocks (history preserved in git + `archive/`).
- **Expected impact:** smaller, faster-to-author screen. **Dependencies:** production validation.

## Long term — strategic (v1.2.x → v2.0.0)

### R-10 · Add lightweight commit-outcome telemetry · Effort M
- The new flag model (`varAllOK` + tier flags + `varSubmissionID`) already knows what succeeded/failed per submission. Log that to a telemetry list or Application Insights so partial-failure rates become measurable and the cascade can be validated with real data.

### R-11 · Finish the classic → modern control migration · Effort L · (carried roadmap item)
- Complete the migration screen-by-screen; validate accessibility (labels, tab order, contrast) — note the App Checker also flags 229 `acc-AccessibleLabelNeeded` and related accessibility items to burn down over time.

### R-12 · Formalize the RBAC default / unknown-user policy · Effort M · (carried roadmap item)
- Default is currently `User`; `docs/PROJECT_STATUS.md` flags `AccessDenied` as the ideal once `DeskAccessControl` is fully populated. Decide and implement; populate `DeskAccessControl` for all intended users.

### R-13 · Optional: externalize config (feature flags, `varDebugMode`) · Effort L
- **Note:** the hard-coded PM/admin email addresses (KI-05/06) are **intentional and kept by design** for resilience. If desired *for maintainability only*, a future config layer (environment variables / a config list) could centralize distribution lists and a `varDebugMode` toggle — but this is optional, not required.

### R-14 · Automated pre-release quality gate · Effort M
- **Rationale:** the binding-error regression (KI-02) would have been caught automatically.
- **Action:** add a release script that parses `CanvasManifest.BindingErrorCount` and cross-checks `varRepoVersion` / `AppDescription` / `VERSION` / `.msapp` filename for agreement; fail the release on mismatch.
- **Expected impact:** regressions and version-label mismatches can't silently ship again. **Dependencies:** existing ALM scripts under `src/scripts/`.
