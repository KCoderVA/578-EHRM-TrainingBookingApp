## Medium term — next minor cycle (v1.4.0)

### R-05 · Begin the accessibility burn-down · Effort L · addresses KI-02
- **Rationale:** the modern-control migration pushed App-Checker findings to `acc-TabIndexShouldBeDefinedForInteractiveControl` 294, `acc-FocusBorderShouldBeVisible` 177, `acc-AccessibleLabelNeeded` 300.
- **Action:** remediate screen-by-screen (accessible labels, tab order, focus visibility, contrast), prioritizing the booking path (`Confirm`, `DeskSelect`, calendars). Track the SARIF totals release-over-release.
- **Expected impact:** measurable Section 508 progress. **Dependencies:** none.

### R-06 · Finish the `Learning Lab Sessions` → `MasterScheduleList` migration · Effort M · addresses KI-04, KI-07
- **Rationale:** the migration is mid-flight — active use deprecated, but the data source and commented queries remain.
- **Action:** once `MasterScheduleList` fully covers the picker, delete the commented `Learning Lab Sessions` queries in `POCSUPERVISOR`, remove the `Learning Lab Sessions` data source on the next export, and keep `Learning Labs Library` (still used by the class picker).
- **Expected impact:** a single, app-owned scheduling source; smaller `POCSUPERVISOR`. **Dependencies:** production validation of the new path.

### R-07 · Resolve `Screen1`'s entry point · Effort S–M · addresses KI-11
- **Rationale:** the Power BI tile is fixed, but the screen still has a placeholder `Button1` and no menu entry.
- **Action:** add an admin/leadership `colMenu` entry (or a deliberate print link) and remove `Button1`; confirm the new workspace/dashboard/tile is shared with the intended audience.
- **Expected impact:** the restored dashboard is actually reachable. **Dependencies:** Power BI report sharing.

### R-08 · Keep the debug tier out of production data · Effort S · addresses KI-09
- **Rationale:** `"DEBUG …"` rows still land in `'Desk Reservations'` on total failure.
- **Action:** route debug writes to a diagnostics list (or flag + exclude from galleries/Power BI); gate behind `varDebugMode`.
- **Expected impact:** clean reservation data and reporting. **Dependencies:** none.

### R-09 · Remove dead code after the new paths are proven · Effort S · addresses KI-04, KI-10
- **Rationale:** commented `btnOldSubmit` (Confirm) and the legacy `POCSUPERVISOR` queries inflate those files.
- **Action:** delete the `/* … */` / `//` legacy blocks once the orchestration, cascade, and `MasterScheduleList` path are production-validated (history preserved in git + `archive/`).
- **Expected impact:** smaller, faster-to-author screens. **Dependencies:** production validation.

### R-10 · Ship the `MyAppts` self-cancellation workflow · Effort M · addresses KI-12
- **Rationale:** users still cannot self-cancel; the prior stub control was renamed/removed.
- **Action:** implement the cancel `Patch` (status/cancelled flag), confirmation prompt, and optional cancellation email; make it series-vs-single aware to match the booking cascade.
- **Expected impact:** complete booking lifecycle; less admin overhead. **Dependencies:** SharePoint status column.

### R-11 · Finish / verify the `group` → `groupContainer` migration · Effort S–M · addresses KI-06
- **Rationale:** the `group` template was removed from the registry while some `group` controls persist.
- **Action:** verify all remaining `As group:` controls render correctly, or migrate them to `groupContainer`.
- **Expected impact:** template registry and controls stay consistent. **Dependencies:** none.

## Long term — strategic (v1.4.x → v2.0.0)

### R-12 · Add lightweight commit-outcome telemetry · Effort M
- The tier-flag model (`varAllOK` + tier flags + `varSubmissionID`) already knows what succeeded/failed per submission. Log it to a telemetry list or Application Insights so partial-failure rates become measurable and the cascade can be validated with real data.

### R-13 · Auto-sync the in-app admin changelog · Effort M
- `ReleaseNotes` embeds a point-in-time render of `CHANGELOG.md`; add an ALM step to regenerate the HTML at release time (or source it from a SharePoint list) so the in-app changelog never drifts.

### R-14 · Formalize the RBAC default / unknown-user policy · Effort M
- Default is currently `User`; `docs/PROJECT_STATUS.md` flags `AccessDenied` as the ideal once `DeskAccessControl` is fully populated. Decide and implement; populate `DeskAccessControl` for all intended users. *(The richer `ManageUsers` Entra/Graph capture added in v1.3.5 makes populating these records easier.)*

### R-15 · Automated pre-release quality gate · Effort M · addresses KI-01, version drift
- **Rationale:** a script that parses `CanvasManifest.BindingErrorCount` and cross-checks `varRepoVersion` / `AppDescription` / `VERSION` / `.msapp` filename would have caught the prior 0 → 24 regression and any version drift automatically.
- **Action:** add it to the ALM scripts under `src/scripts/` and fail the release on `BindingErrorCount > 0` or a version mismatch.
- **Expected impact:** regressions and label mismatches can't silently ship. **Dependencies:** existing ALM scripts.

### R-16 · Optional: externalize config (feature flags, `varDebugMode`, distribution lists) · Effort L
- **Note:** the hard-coded PM/admin emails (`KI-13`/`KI-14`) are **intentional and kept by design** for resilience. If desired *for maintainability only*, a future config layer (environment variables / a config list) could centralize distribution lists and a `varDebugMode` toggle — optional, not required.

### R-17 · Consider a Teams notification (only if the connector returns) · Effort M
- v1.3.5 removed the unused Teams connector. If a Teams channel notification is ever wanted (e.g., post an adaptive card to coordinators when `varAllOK = true`), re-add the connection deliberately and wire it — don't reintroduce an unwired placeholder.
