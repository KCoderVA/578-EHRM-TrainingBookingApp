## Short-term (pre and immediate post go-live)

| Priority | Recommendation | Rationale | Expected impact | Rough effort | Dependencies |
|---|---|---|---|---|---|
| P1 | Burn down remaining App Checker issues (`BindingErrorCount 120`) | Residual bindings can become runtime defects under production data | Lower incident risk during first-live week | Medium | Access to Power Apps Studio checker output and screen owners |
| P1 | Execute environment readiness checklist for all newly bound lists/sites | `Connections.json` now binds additional sites/lists; missing permissions will break flows/screens | Prevents go-live failures caused by data-source resolution errors | Medium | SharePoint admins, connection references, environment variables |
| P1 | Validate backup-write and main-write reconciliation in `Confirm` | Main + fallback + backup pattern is robust but needs traceable success semantics | Higher data durability and operational confidence | Medium | backup list availability, test data, monitoring logs |
| P1 | Decide and enforce unknown-user default access policy | Current default auto-provisions as `User`; security policy may require deny-by-default | Reduces unauthorized booking surface and audit risk | Medium | Governance decision, DeskAccessControl policy update |
| P2 | Replace hard-coded identity gates with role- and config-driven checks | Hard-coded account checks do not scale and are brittle | Better maintainability and secure admin model | Medium | Config store / environment variable / list-backed role model |

## Security and privacy recommendations

1. Minimize direct embedding of tenant-specific URLs and service mailbox strings in formulas where possible.
2. Validate that all tracked source/docs are sanitized for public/enterprise repository visibility before each release.
3. Move toward deny-by-default access provisioning with explicit role grants, aligned to organizational policy.

---

## Testing recommendations

1. Define a go-live smoke suite covering:
   - booking creation
   - attendee-on-behalf flow
   - recurrence path
   - backup patch path
   - user-management access controls
2. Add negative-path tests:
   - missing list permission
   - missing list binding
   - malformed attendee selection
3. Validate post-submit reconciliation for fields deferred to automation (Outlook IDs, trainer/reminder lifecycle).

---

## Operational recommendation for next semantic bump

Use the post-v0.12.2 release cycle to prioritize hardening over feature breadth. The app has reached a strong functional milestone; the highest ROI now is reliability, observability, access-policy rigor, and environment portability.
