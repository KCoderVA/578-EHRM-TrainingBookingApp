## Executive summary

v1.3.5 is a **data-source-modernization and reliability release** that also completes the platform's classic → modern control migration. There are **no new screens and no removed screens**. The headline stories are:

1. **The supervisor scheduling experience (`POCSUPERVISOR`) was re-based onto the app's own `MasterScheduleList`** — moving off the national **`Learning Lab Sessions`** SharePoint list — using stable `_text` columns and an active-session filter, and adding a **one-click tool to back-fill a new `scenarioDescription_multitext` column**.
2. **The prior release's top defect was fixed:** the `Success` screen's 24 binding errors (v1.1.20 `KI-02`) were corrected — `CanvasManifest.BindingErrorCount` dropped **24 → 3**, and the App Checker type-equality error class disappeared.
3. **User administration got richer:** `ManageUsers` now captures a full **Entra/Graph profile and manager chain** (department, job title, hire date, network account, address, manager + photo) plus the approver's identity.
4. **The unused Microsoft Teams connector was removed** (v1.1.20 `KI-03` closed).
5. **The printable Power BI dashboard (`Screen1`) was re-pointed to a new report and re-enabled.**
6. **App-wide modernization:** classic glyph icons → modern `icon`, printable/phone screen layout templates flattened, and the legacy `group` control retired — which also *raised* accessibility App-Checker findings that now form the main technical-debt backlog.

## Functional impact & design rationale

### 1. Supervisor scheduling re-based on `MasterScheduleList` (`POCSUPERVISOR`)

**Before:** the supervisor screen's role / scenario / date-time pickers read the national **`Learning Lab Sessions`** SharePoint list (via `col_nationalEHRMLearningLabSessions`), matching on lookup/choice columns (`Role.Value`, `Title`, `Scenario.Value`).

**After:** the active logic reads the app's own **`MasterScheduleList`** through stable text columns — `RoleName_text`, `ScenarioName_text`, `TrainingCombinedDateTime_text`, `LocationCombined_text` — and only shows sessions where `sessionActive_text` is blank or not `"false"`. The old queries are commented out in place (with a dated developer note), so the change is reversible and auditable.

**Why it matters:** `MasterScheduleList` is owned and controlled by this app/team, whereas `Learning Lab Sessions` is external national reference data. Basing scheduling on the app's own list makes the picker more predictable, filterable, and independent of upstream changes — and lets inactive sessions be hidden without deleting them.

### 2. New `scenarioDescription_multitext` column + in-app back-fill (`POCSUPERVISOR` / `MasterScheduleList`)

A new **multi-line text** column, `scenarioDescription_multitext`, was added to `MasterScheduleList`, and a supervisor button (`btn_patchMasterScheduleList_scenarioDescription_multitext`) back-fills it: it computes each scenario's description and `Patch`es only the rows that are blank or out-of-date.

**Why it matters:** scenario descriptions can now be maintained as first-class data on the schedule list (rather than being derived on the fly), which simplifies display and downstream reporting. *(Because it's a manual, one-click bulk-patch tool, its long-term home — supervisor feature vs. one-time admin utility — should be confirmed; see recommendations.)*

### 3. `Success` status-summary fix — 24 → 3 binding errors (`Success`)

**Before:** the v1.1.20 booking-commit refactor retired the old flag variables (`varMainOK`, `varBackupOK`, `varBackupSimpleOK`) but the `Success` screen still referenced them, producing **24** binding errors (`KI-02`).

**After:** the `Success` status summary was rewritten against the current tier flags — `varDetailedListPatchOK`, `varFallbackOK`, `varSimpleListPatchOK`, `varEmailOK` — the SuperUser-patch line is now gated by `user_IsSuperUser`, and an email-notification status line was added. `BindingErrorCount` fell **24 → 3** and the App-Checker type-equality error class was cleared.

**Why it matters:** this was the single open functional defect from the prior cycle. Users now see an accurate per-step success/failure summary after booking, and the app's health signal is green-again (three residual binding errors remain to chase — see known issues).

### 4. Richer Entra/Graph user + manager capture (`ManageUsers`)

The admin "Manage Users" screen now hydrates a full profile for the user being edited via `Office365Users.UserProfileV2` (display name, email, given name, department, job title, hire date, network account/mail-nickname, and a combined street/city/state/postal/company address) and the **manager chain** via `Office365Users.ManagerV2` (name, email, department, job title, photo). It also records the approving admin's identity.

**Why it matters:** access decisions and audit trails benefit from complete, directory-sourced identity and reporting-line data captured at edit time — with no SharePoint schema change required (the values populate existing `DeskAccessControl` columns).

### 5. Live Graph people-pickers (`POCSUPERVISOR`, `ManageUsers`)

Person search on both screens moved from SharePoint choice columns to live `Office365Users.SearchUserV2` graph search (impersonation-aware on `POCSUPERVISOR`).

**Why it matters:** directory search returns current, tenant-wide results and is not limited to values previously seen in a SharePoint choice column.

### 6. Microsoft Teams connector removed (connections)

The Teams connection and its data-source/WADL files — added in v1.1.20 as an unwired placeholder (`KI-03`) and never referenced by any formula — were removed.

**Why it matters:** the app no longer advertises a dependency it doesn't use, reducing connector sprawl and import friction for anyone recreating the app.

### 7. Power BI dashboard re-pointed & re-enabled (`Screen1`)

The embedded Power BI tile was re-pointed to a new workspace/dashboard/tile and the `Visible: =false` that hid it in v1.1.20 was removed, restoring the printable dashboard view. *(The screen still carries a placeholder `Button1` and is not yet wired into the menu — see known issues `KI-07`.)*

### 8. Classic → modern control modernization (app-wide)

Classic glyph icons were migrated to the modern `icon` control, printable/phone screen layout templates were flattened to plain screens, and the legacy `group` control was retired in favor of `groupContainer`. This is largely tooling-driven but forward-looking.

**Trade-off:** modern controls each expect explicit accessibility properties, so App-Checker accessibility findings rose (tab-index, focus-border, accessible-label). Functional correctness improved even as this accessibility backlog grew — it is now the top maintenance theme (see [`v1.3.5_recommendations.md`](v1.3.5_recommendations.md)).

## Cross-component version notes

- **Project vs. component version.** Per this repo's hybrid versioning policy, the project-wide `VERSION` advances **`1.2.8 → 1.3.5`** to align the deployable-bundle version with this Canvas-app component version. `src/solution.xml` is aligned to `1.3.5` as the project-wide bundle.
- **SharePoint implication.** The live `MasterScheduleList` must carry the new **`scenarioDescription_multitext`** column (and the `_text` scheduling columns the picker now reads). The extracted schema under `src/sharePoint/` should be re-exported to include it (carried follow-up `KI-04`).
- **Power BI implication.** `Screen1` now embeds a **different** workspace/dashboard/tile; ensure the new report exists and is shared with app users in the GOV tenant.
- **Power Automate.** No direct flow calls are made by the app; companion flows in [`../powerAutomate/`](../powerAutomate/) are unaffected by these Canvas changes.
