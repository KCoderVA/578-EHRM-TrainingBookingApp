## Detailed register

### KI-01 — 3 residual binding errors remain (down from 24) · Medium · bug · 🆕
**Evidence:** `CanvasManifest.json → BindingErrorCount: 3` (was `24` in v1.1.20). The `Success`-screen rework (diff §3.5) cleared the bulk of the prior errors and the App-Checker `app-ErrIncompatibleTypesForEquality-Left-Right` class (13 in v1.1.20) no longer appears in the top rules.
**Impact:** three unresolved binding errors still ship; location not identified from the SARIF alone (the SARIF `level` field is empty in this export).
**Suggested fix:** open App Checker in Studio, sort by severity, and resolve the 3 remaining binding errors; target `BindingErrorCount = 0`.

### KI-02 — Accessibility debt grew from the modern-control migration · Medium · accessibility · 🆕
**Evidence (App Checker totals, v1.1.20 → v1.3.5):** total results `695 → 1,075`; `acc-TabIndexShouldBeDefinedForInteractiveControl` `93 → 294`; `acc-FocusBorderShouldBeVisible` `52 → 177`; `acc-AccessibleLabelNeeded` `229 → 300`.
**Root cause:** the classic → modern control migration (diff §7) introduced many controls that individually require explicit `TabIndex`, focus-border, and accessible-label properties.
**Impact:** Section 508 / accessibility conformance gap widened even though functional correctness improved.
**Suggested fix:** burn down accessibility findings screen-by-screen (labels, tab order, focus visibility); prioritize the high-traffic booking path (`Confirm`, `DeskSelect`, calendars).

### KI-03 — Leftover commented impersonation line with a VA email in `App.OnStart` · Low · tech-debt / PII-in-comment · 🆕
**Evidence:** `Src/App.fx.yaml` `App.OnStart` adds `//Set(varRealEmail, Lower("[REDACTED]@va.gov"));` — a commented developer impersonation-test line containing a specific VA user's email address (redacted here in this public-facing doc; the literal is present in the app source).
**Impact:** dead code that publishes a named individual's email into tracked source; harmless at runtime.
**Suggested fix:** delete the commented line before publishing (or replace with a neutral placeholder). Also covered by the sanitization policy in `KI-15`.

### KI-04 — `POCSUPERVISOR` ships heavy work-in-progress commented code + dated dev note · Low · tech-debt / incomplete · 🆕
**Evidence:** `Src/POCSUPERVISOR.fx.yaml` retains many commented-out legacy `Learning Lab Sessions` queries and a dated note `//////ATTN KYLE!  AS OF 09/23/2026:  Testing alternative formula`, alongside the active `MasterScheduleList` logic.
**Impact:** the screen is visibly mid-experiment; large commented blocks inflate the file and can confuse future maintainers.
**Suggested fix:** once the `MasterScheduleList` path is production-validated, delete the legacy commented queries (history is preserved in git + `archive/`).

### KI-05 — Scenario-description back-fill button ships in the live app · Low–Med · data-tooling in UI · 🆕
**Evidence:** `Src/POCSUPERVISOR.fx.yaml` `btn_patchMasterScheduleList_scenarioDescription_multitext` performs a bulk `Patch(MasterScheduleList, … {scenarioDescription_multitext: _desc})`.
**Impact:** a bulk data-migration/maintenance action is exposed in the running app; if reachable by a non-admin it could rewrite schedule data.
**Suggested fix:** confirm intent — if it's a one-time back-fill, gate it behind an admin role (or remove after use); if it's an ongoing supervisor feature, add a confirmation prompt and restrict visibility.

### KI-06 — Legacy `group` template removed while some `group` controls persist · Low · platform / tech-debt · 🆕
**Evidence:** `ControlTemplates.json` removed the `group` template (`http://microsoft.com/appmagic/group`); yet some `group` controls remain in source (e.g. `grpConfirmDelete` in `ManageDesks`).
**Impact:** potential inconsistency between the template registry and controls that still declare `As group:`; likely handled by the runtime but worth confirming.
**Suggested fix:** in Studio, verify all remaining `group` controls render/behave correctly, or finish migrating them to `groupContainer`.

### KI-07 — `Learning Lab Sessions` mid-migration (commented, data source still present) · Low · tech-debt · 🆕
**Evidence:** active use is deprecated (Dashboard `Refresh('Learning Lab Sessions')` removed; `POCSUPERVISOR` queries commented) but the `Learning Lab Sessions` data source and connection remain, and the string count actually rose (28 → 33) due to commented references.
**Impact:** a partially-deprecated data source remains wired; ambiguous state for maintainers.
**Suggested fix:** once `MasterScheduleList` fully covers the need, remove the `Learning Lab Sessions` data source (and the commented queries) on the next export; keep `Learning Labs Library` (still used for the class picker).

### KI-08 — `sessionActive_text` **and** `scenarioDescription_multitext` not yet in extracted SharePoint schema · Medium · data-integrity (deferred) · ➡️ Carried (expanded)
**Evidence:** the app reads `MasterScheduleList.sessionActive_text` (carried from v1.1.20 `KI-04`) and now also writes/reads the new `scenarioDescription_multitext` column, but the extracted SharePoint documents under `src/sharePoint/` do not yet include these columns.
**Impact:** the shipped picker filter and back-fill only work if the live list has these columns; the tracked schema drifts from the app.
**Suggested fix:** confirm/populate both columns on the live `MasterScheduleList`, then re-extract the schema into `src/sharePoint/` and update its README.

### KI-09 — Debug tier still writes `"DEBUG …"` rows into production reservation list · Medium · data-integrity · ➡️ Carried
**Evidence:** `Src/Confirm.fx.yaml` still contains `btnPatch_debugSimplified` (6 matches) and `"DEBUG …"` row titles (8 matches) written to `'Desk Reservations'` on total failure.
**Impact:** last-resort diagnostics can land in live data and skew reporting/Power BI.
**Suggested fix:** route debug writes to a diagnostics list (or flag + exclude from galleries/reports); gate behind a `varDebugMode`.

### KI-10 — Large commented-out dead code (`btnOldSubmit`) · Low · tech-debt · ➡️ Carried
**Evidence:** `Src/Confirm.fx.yaml` still carries the commented `btnOldSubmit` block (7 matches) and inline copies from the pre-v1.1.20 commit flow.
**Suggested fix:** delete once the orchestration + cascade are production-proven (history preserved in git + `archive/`). See also `KI-04`.

### KI-11 — `Screen1` still unlinked (placeholder `Button1`, absent from `colMenu`) · Medium · incomplete feature · ➡️ Carried (changed)
**Evidence:** the Power BI portion improved (re-pointed + re-enabled, diff §3.7), but `Src/Screen1.fx.yaml` still declares placeholder `Button1 As …` (2 matches) and `Src/App.fx.yaml` has **0** `Screen1` references (no `colMenu` entry / inbound `Navigate()`).
**Impact:** a partially-finished screen ships with no user entry point.
**Suggested fix:** finish it behind an admin role (remove `Button1`) and add a menu entry, or keep it as an intentional print-only target reached by a deliberate link.

### KI-12 — `MyAppts` self-cancellation still not implemented · Medium · incomplete feature · ➡️ Carried (verify)
**Evidence:** `Src/MyAppts.fx.yaml` changed only via icon modernization this cycle; no cancel `Patch` logic was added. The previously-cited `Button3_9` ("Cancel This") control name is **no longer present** (0 matches), so the stub was renamed or removed.
**Impact:** users still appear unable to self-cancel a reservation.
**Suggested fix:** confirm current state in Studio; implement the cancel `Patch` (status/cancelled flag) with a confirmation prompt and optional notification, series-vs-single aware.

### KI-13 — Developer/admin email gates hard-coded in `Confirm` / `App` · Info · by design · ✔️ Accepted
**Evidence:** `App.OnStart` impersonation gate now uses `Lower(User().Email) = "kyle.coder@va.gov"`; `Confirm` retains its admin-account diagnostic branch.
**Status (per developer):** intentional — hard-coded for the project owner/admin so the app keeps working and remains diagnosable even during a data-source problem. **Kept by design.**

### KI-14 — Admin/PM email addresses hard-coded in confirmation-email `Cc` · Info · by design · ✔️ Accepted
**Evidence:** `Confirm` `btnOutlook_SendAsEmail` `Cc` still concatenates the project managers/admins (`Kyle.Coder@va.gov` plus two additional project-manager addresses — redacted here; present in the app source).
**Status (per developer):** intentional so notifications always reach the PMs. **Kept by design.**

### KI-15 — Environment-specific GUIDs / site URLs in tracked source · Low · accepted policy · ➡️ Carried
**Evidence:** unpacked `Src/**` contains tenant/environment GUIDs, SharePoint site URLs, and Power BI GOV embed IDs — **now including the new `Screen1` workspace/dashboard/tile IDs** (diff §3.7). *(Power BI embed IDs are report identifiers, not credentials.)*
**Status:** the repo publishes unpacked source with a sanitization note in `src/powerApps/README.md`; this remains a standing policy decision, not a v1.3.5 blocker. Combine with the `KI-03` comment cleanup before publishing.

### KI-16 — `HtmlText3` `Parent.Visible` guard (from v1.1.20) unverified this cycle · Low · performance · ➡️ Carried
**Evidence:** `Confirm` changed minimally this cycle; the v1.1.20 note that `HtmlText3` lost its `If(Parent.Visible = true, …)` short-circuit was not re-examined in depth.
**Suggested fix:** restore the `Parent.Visible` short-circuit if the unconditional evaluation was unintended (minor).
